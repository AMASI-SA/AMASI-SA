# تصميم محدود للمراجعة — غير منفذ
القيود التالية مقترح داخلي مشروط بالسياسة المعتمدة، وليست اختيارًا ضريبيًا أو تفويضًا للترحيل. SAR فقط. لا نقل تاريخ؛ افتتاحيات P07.

## المستندات والأحداث المستقلة
- Purchase invoice: رأس + invoice line IDs + المورد + العدد والسعر والخصم والضريبة والمرفق؛ draft/reviewed/posted/reversed مع version. حفظ draft لا قيد ولا تغيير تكلفة أو كمية.
- Goods receipt: receipt ID مستقل وبنود مستقلة تربط invoice line أو طلب شراء/اتفاق توريد مراجعًا إن سبقت الفاتورة؛ مستودع/موقع/received_at/accepted quantities/UOM/delivery evidence. لا تزور فاتورة لتسجيل receipt-first.
- Supplier payment: payment ID مستقل، تنفيذ بنكي موثق وحساب فعلي وتخصيصات للفاتورة أو advance. الحفظ مسودة؛ اعتماد تنفيذ مثبت يرحّل السداد فقط. حقل «المدفوع الآن» ينشئ مسودة دفعة مرتبطة، لا أثر خفي عند حفظ الفاتورة.
- Return: return ID مستقل يربط receipt line والكمية والتكلفة الأصلية وسبب/دليل خروج فعلي. Credit note وcash refund مستقلان، لكل منهما أصل وتخصيص وقيد وهوية.
- Match/allocation: يربط receipt↔invoice وpayment↔invoice/advance وreturn↔credit↔refund بكمية وقيمة قابلة للتتبع. يمنع تجاوز الأصول والتخصيص المزدوج داخل المعاملة.
- حالات متعامدة: document_status وreceipt_progress وpayment_progress وvaluation_status. invoice posted + receipt partial + payment partial حالة صحيحة؛ لا status واحدة توهم اكتمال الجميع.

## الفصل المقترح بين التوقيتات
للتوضيح: clearing_purchase_asset = فواتير قبل الاستلام؛ GRNI = التزام استلام قبل الفاتورة. أسماء حسابات منطقية **لم تعتمد أو تسجل**. invoice net=B وinput tax eligible=T وgross=B+T؛ الضريبة غير المستردة جزء من تكلفة الاقتناء المؤهلة وفق القرار، ولا تدخل T. السياسة والأدلة تحدد تاريخ الاستحقاق/أهلية الضريبة.

| الحالة | المقترح المشروط | حارس منع التكرار/القرار |
|---|---|---|
| مسودة فاتورة/دفعة/استلام | لا قيد؛ معاينة فقط | لا تحديث cost_avg أو كمية معتمدة |
| فاتورة قبل الاستلام | عند اعتماد الالتزام بدليله: Dr clearing B + Dr eligible input VAT T / Cr AP B+T | لا مخزون قبل الاستلام. توقيت ضريبة المدخلات/الملكية يحتاج اعتماد؛ نقص الدليل = needs_review |
| استلام بعد الفاتورة | Dr inventory received value / Cr clearing بالقيمة المخصصة؛ VAT لا تتكرر | partial يترك clearing والمتبقي، لا إعلان اكتمال |
| استلام قبل الفاتورة | إثبات كمية فعلية؛ إن وجدت تكلفة موثقة معتمدة Dr inventory / Cr GRNI؛ وإلا quantity accepted + valuation pending بلا قيمة صفر معتمدة ولا COGS نهائية | يلزم سياسة التسعير المؤقت والملكية؛ لا صرف مقيم قبل كفاية الدليل |
| فاتورة بعد الاستلام | Dr GRNI للجزء المطابق + Dr clearing للجزء غير المستلم + Dr eligible VAT / Cr AP؛ فرق السعر حدث valuation adjustment مستقل | الفروقات توزع على المتبقي/WIP/COGS حسب trace معتمد؛ لا تعديل snapshot قديم |
| مقدم للمورد | Dr supplier advance / Cr bank؛ لا استلام ولا شراء ولا ضريبة تلقائيًا | taxable advance أو فاتورة دفعة مقدمة = مراجعة ضريبية مستقلة؛ لا نقل سياسة مقدم العميل |
| تسوية مقدم مع فاتورة | Dr AP / Cr supplier advance بقيمة تخصيص مثبتة | ليست حركة بنك أخرى ولا شراء جديد |
| دفع جزئي/كامل | Dr AP / Cr bank بالقيمة المدفوعة فقط | لا debit inventory أو input VAT مجددًا؛ مبلغ فوق AP يتطلب advance صريحًا |
| خروج مرتجع للمورد | Dr supplier-return clearing / Cr inventory بالقيمة الدفترية المعتمدة للأصل | كمية return <= المتاح المؤهل من الأصل؛ لا عكس الفاتورة كلها |
| إشعار دائن | Dr AP أو supplier refund receivable / Cr return clearing + Cr eligible input VAT reversal؛ فرق مثبت يعالج بحدث مستقل | يعتمد على الأصل والضريبة الأصلية والأهلية، لا المعدل الحالي. refund receivable إذا سدد الأصل، لا AP يدوي سالب مخفي |
| رد مال المورد | Dr bank / Cr supplier refund receivable | بلا كمية أو شراء أو ضريبة ثانية |
| إشعار دائن بلا رد بضاعة | تعديل قيمة موثق مستقل على الموجود/WIP/COGS حسب trace والسياسة | لا اختراع كمية سالبة. approval للفروقات مطلوب |
| إشعار دائن قبل خروج البضاعة | حفظه needs_review أو التزام إعادة مصنف وفق سياسة معتمدة؛ لا تنزيل مخزون غير خارج | لا تنفيذ تلقائي حتى يحسم توقيت الحق/الخروج |
| تلف/هدر/فرق استلام | quantity exception ومستند قرار منفصل | لا قبول زائد ولا توزيع مصروف خفي |

## المتوسط المرجح دون إعادة فتح القرار
الهدف المعتمد retained: moving weighted average للمواد والبضائع المتجانسة من الاستلامات الفعلية.
لكل owner + inventory item + variant/configuration + base UOM + cost pool:
Q_new=Q_on_hand+Q_accepted; V_new=V_on_hand+net allocated acquisition value; AVG=V_new/Q_new.
الكمية المصروفة تخفض Q وV بالتكلفة المجمدة وقت الصرف؛ لذلك لا يصح متوسط كل فواتير العمر. الوحدات كـDecimal، الأموال halalas، average داخلي بدقة أعلى وتوزيع فرق التقريب على آخر حركة متبقية لمنع انجراف V. لا float ولا rounding الكمية إلى منزلتين عالميًا.
المستودع بعد كمية مستقل؛ نطاق pool بين الفروع قرار مطلوب، لا خلط ضمني. تحويل بين مواقع نفس pool يحرك الكمية فقط ولا ينشئ شراء أو ربح.
أصول الاستلام تحفظ تكلفة ومصدرًا؛ الصرف يحفظ average وقت الحدث وpolicy version. return-from-stock عند تغيّر average عن سعر الأصل يتطلب سياسة فرق تقييم معتمدة، فلا يطرح سعر أصل يخلق مخزونًا سالب القيمة بلا مراجعة.
الخصم والضريبة غير المستردة ونقل الاقتناء الموثق تخصص بقواعد معلنة. الشحن المتأخر لا يعيد كتابة التاريخ؛ حدث تعديل بتاريخ مفتوح مع أثر منفصل على الموجود/المستهلك. لا نفترض كل مصروف نقل مؤهلًا للرسملة.

## أقل تصنيع يغطي طلب العميل → قماش → قطعة
1. ربط job صغير بـowner/order_number/canonical order_item_id/piece_id وconfiguration snapshot؛ بلا MRP أو تخطيط مصانع.
2. مادة stockable مرتبطة resource_id مستقل عن service. base UOM=meter مثال، conversion رول→متر موثق ومؤرخ؛ لا تحويل الاسم تلقائيًا. مشترياتها واستلاماتها تدخل material pool بالمتوسط المرجح.
3. صرف فعلي measured issue إلى job: Dr WIP / Cr materials، مع receipt/value lineage وكمية فعلية. binding quantity اقتراح لا دليل صرف. مواد عند مقاول تبقى موقع عهدة/مقاول منفصلًا إن بقيت ملكيتها للمنشأة.
4. خدمات تصنيع مباشرة مكتملة ومثبتة: Dr WIP / Cr supplier AP أو direct-cost clearing حسب سبق اعتماد الفاتورة. نفس service completion لا ينشئ أيضًا مصروف تكلفة منتج في المسار القديم. لا إعادة استحقاق أجور سبق إثباتها؛ تخصيصها من clearing مصدر واحد.
5. إعادة مادة غير مستخدمة: Dr materials / Cr WIP بالتكلفة الأصلية للصرف؛ لا سعر الكتالوج الحالي. الهدر الطبيعي/غير الطبيعي وفائض القماش قرار موثق؛ المثال في fixture يفترض خسارة غير طبيعية صريحة فقط.
6. اكتمال قطعة واحدة: Dr finished goods / Cr WIP بإجمالي موادها المستخدمة + التكاليف المباشرة المعتمدة. هوية القطعة/configuration لا تدمج بمتوسط منتج مختلف.
7. انتقال تكلفة البيع عند حدث التسليم/الاعتراف الذي تعتمده النواة: Dr COGS / Cr finished goods؛ ارتباط واحد مع الطلب يمنع cost snapshot كتالوج إضافية في GL. توقيت النواة وناقص التكلفة يحتاج عقد قبل التنفيذ.
8. لا finished stock جاهز ≠ تكلفة صفر. missing receipts/issue/labor evidence تجعل cost_status=pending، وربح الطلب غير نهائي. لا مخزون سالب أو افتتاحية وهمية لاستكمال الرحلة.
9. مرتجع عميل لقطعة مصنعة، أو إعادة عمل/إلغاء بعد بدء العمل، يتطلب أصل القطعة وفحص حالتها وتحديد إعادة الإدخال/خسارة؛ لا يعيد قماشًا مستهلكًا تلقائيًا. خارج المثال المقبول حتى سياسة معتمدة.

المتوسط المرجح للمواد والبضائع المشتركة، actual job accumulation للقطعة المخصصة. لا تحميل اعتباطي لإيجار/إدارة/تكاليف غير مباشرة، ولا تطبيق متوسط المواد على كل المنتجات النهائية دون تمييز. الخدمات ليست كميات مخزون.

## واجهة مستقبلية محدودة
تبويبات فاتورة/استلام/ذمة المورد داخل صفحة واحدة؛ الإجراءات منفصلة: حفظ مسودة، مراجعة/اعتماد فاتورة، تسجيل استلام، تسجيل دفعة، مرتجع/إشعار دائن. تظهر أرقام invoice/received/remaining/paid/valuation pending مستقلة. receipt-first يستخدم مسودة اتفاق توريد لا invoice وهمية. لكل إجراء معاينة وأصل ومجموعة قيد قابلة للفتح؛ المبلغ والكمية لا يحررهما مستخدم بعد الترحيل، والتصحيح بوثيقة جديدة.
