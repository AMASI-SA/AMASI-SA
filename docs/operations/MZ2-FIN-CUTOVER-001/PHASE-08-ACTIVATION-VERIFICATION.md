# P08 — التفعيل والتحقق بعد القطع

الحالة: **BLOCKED_BY_P07**  
بوابة الخروج: **LOCKED**

## الهدف

إثبات أن ميزان 2 يعمل بعد القطع كنظام محاسبي مستقل: كل حدث تشغيلي جديد ينتج قيدًا واحدًا متوازنًا وقابلًا للتدقيق، ولا توجد قراءة مالية أو كتابة من ميزان القديم.

## شروط البدء

- P07 `COMPLETE`.
- `12/12` جاهزية.
- قيد افتتاحي مرحل ومتحقق.
- `safe_active=true` للعملية نفسها.
- Production SHA معروف ومتحقق عبر release guard.

## نطاق التحقق

يختبر حدثًا فعليًا أو تجريبيًا مصرحًا لكل مسار:

- طلب/بيع وتسوية سلة.
- تسوية تمارا.
- تسوية تابي.
- تسوية إمكان.
- شحنة خارجية وتحصيل COD.
- توصيل مندوب متجر COD.
- توصيل مندوب متجر prepaid.
- فاتورة شراء واستلام مخزون.
- سداد مورد.
- حركة مالية عامة صحيحة.
- استحقاق راتب وسداد.
- التزام دوري وسداد.
- عكس قيد مصرح.

## قاعدة القيد الواحد

لكل event id أو statement id أو invoice id أو assignment/delivery id:

- مجموعة قيد واحدة فقط.
- idempotency key ثابت.
- إعادة webhook أو الطلب لا تكرر المجموعة.
- كل الأرجل تحمل المصدر والمرجع والمستخدم والوقت.
- المدين يساوي الدائن.
- المستند أو الحدث قابل للفتح من القيد والعكس.

## التحقق من الاستقلال عن ميزان القديم

يجب إثبات:

- لا endpoint مالي يقرأ رصيدًا أو مبيعات أو تكلفة أو ذمة من قاعدة/مجموعة Legacy.
- القيم المنسوخة سابقًا أصبحت إعدادات مستقلة في ميزان 2.
- تعطيل الوصول إلى ميزان القديم لا يغير القيود أو التقارير الجديدة.
- لا عملية backfill تلقائية تعمل بعد التفعيل.
- أي حقل provenance قديم يبقى للتدقيق ولا يستخدم كمصدر مالي معتمد.

## المطابقة اليومية الأولى

لمدة تشغيل أولية معتمدة، يراجع النظام:

- عدد الأحداث مقابل عدد مجموعات القيود.
- المجموعات غير المتوازنة.
- التكرارات.
- المستندات بلا قيد والقيود بلا مستند.
- التسويات مقابل البنك.
- COD مقابل الشركات والموصلين.
- المخزون مقابل الاستلام والصرف.
- ذمم الموردين والموظفين.
- الحسابات غير المصنفة.

أي فرق يفتح مهمة `needs_review` ولا يصحح بصمت.

## بروتوكول النشر

كل تغيير Runtime في P08 أو إصلاح بعد القطع يستخدم من `/app`:

1. تحديث workspace إلى `origin/hotfix/prod-snap-meta-final` دون reset قسري.
2. `production_release_guard.py prepare`.
3. `production_release_guard.py prepublish` مباشرة قبل إعادة النشر.
4. Re-publish مرة واحدة.
5. انتظار `Deployment Succeeded` أحدث.
6. `production_release_guard.py verify --url https://mezansalla.com`.
7. عدم تنفيذ كتابة مالية حتى `verified: true` للـSHA نفسه.

## معالجة الخطأ بعد القطع

- لا تعدل القيد التاريخي.
- أوقف المسار المتأثر إذا كان يولد تكرارًا أو عدم توازن.
- سجل المهمة والدليل.
- اعكس القيد الخاطئ عند الحاجة بصلاحية صريحة.
- أصلح الكود واختبره وانشره عبر الحارس.
- أعد تشغيل الحدث فقط بمفتاح idempotency يمنع الازدواج.

لا يجرى rollback لقاعدة البيانات بإزالة القيود المرحلة يدويًا.
