# بروتوكول إدخال بيانات المحاسبة عبر المتصفح السحابي

هذا الملف مخصص لأي محادثة ChatGPT تستلم من المالك مهمة إدخال بيانات في ميزان عبر المتصفح. لا يغير ترتيب المراحل ولا يفتح مرحلة مقفلة.

## قبل فتح المتصفح

1. اقرأ `STATUS.json` وحدد `current_phase`.
2. اقرأ ملف المرحلة الحالية وقائمة الحقول المطلوبة وبوابة الخروج.
3. تأكد أن المطلوب يقع داخل المرحلة الحالية. إن كان لمرحلة لاحقة، اجمعه كمسودة خارجية فقط ولا تدخله نهائيًا ولا تغير حالة المرحلة.
4. افحص صلاحية المستخدم المطلوبة. الإدخال العادي يحفظ مسودة؛ الترحيل والاعتماد يحتاجان تفويضًا صريحًا وصلاحية مستقلة.
5. لا تبدأ أي كتابة مالية إذا كان إصدار Production غير متحقق أو ظهرت نسخة أقدم من الـSHA المطلوب.

## صيغة السؤال للمالك

اطلب الحقول الناقصة فقط، في رسالة واحدة مرتبة. لا تطلب بيانات موجودة بالفعل في الشاشة أو المستند المرفوع. استخدم الأرقام الإنجليزية في الحقول المالية.

مثال:

> أحتاج لإكمال سجل سمسا: تكلفة الشحنة قبل الضريبة، هل السداد مقدم أو آجل، ضريبة الخدمة، شرائح COD وحدود كل شريحة، الرسم الثابت، ضريبة العمولة، والبنك الحالي للتسوية. أرسل القيم فقط، وسأعرض المعاينة قبل الحفظ.

## تصنيف المصدر لكل قيمة

كل حقل يدخل يجب أن يحمل مصدرًا واضحًا حيث تدعم الواجهة ذلك، أو يوثق في سجل الجلسة:

| المصدر | الحالة | هل يسمح بالترحيل؟ |
|---|---|---|
| `provider_statement` | متحقق من كشف مزود | نعم بعد المطابقة والمراجعة |
| `provider_invoice` | متحقق من فاتورة | نعم ضمن الفترة المغطاة |
| `bank_statement` | متحقق بنكيًا | نعم ضمن القطع/التسوية |
| `owner_confirmed` | أكده المالك يدويًا | إعداد تشغيلي؛ لا يثبت رصيدًا افتتاحيًا وحده |
| `legacy_copy` | منسوخ من ميزان القديم | لا؛ مسودة غير معتمدة حتى يؤكدها المالك |
| `system_observed` | رصده النظام من سلة/الطلبات | للمطابقة؛ لا يتغلب على المستند الرسمي |

القيمة المنسوخة من ميزان القديم يجب أن تبقى `unverified` حتى يراجعها المالك. بعد التأكيد لا يعود النظام إلى ميزان القديم؛ تصبح نسخة مستقلة في ميزان 2.

## خطوات التنفيذ في المتصفح

1. افتح الصفحة من داخل قسم `المحاسبة` كلما كانت الصفحة الموحدة متاحة.
2. اقرأ القيم الموجودة ولا تفترض أن الصفر يعني «لا يوجد»؛ قد يعني «غير مُدخل».
3. قارن البيانات بالمستند أو برسالة المالك.
4. أدخل الحقول واحفظ **مسودة** أولًا.
5. اعرض للمالك ملخص المعاينة: المصدر، الإجمالي، العمولة، الضريبة، الصافي، البنك، والفترة.
6. لا تضغط ترحيل/اعتماد/تفعيل إلا بعد موافقة صريحة في نفس المحادثة.
7. بعد الحفظ أعد فتح السجل وتأكد أن القيم استمرت ولم تُحذف أو تتحول وحداتها.
8. اختبر الحدود الحسابية المهمة، خصوصًا شرائح COD عند `1,000` و`3,000` ونحوها.
9. سجل نتيجة الجلسة في ملف المرحلة: ما أُدخل، ما بقي، وأي خطأ واجهة أو API.
10. حدّث `STATUS.json` عبر PR إذا تغيرت حالة بند أو بوابة.

## بيانات يمنع وضعها في GitHub

- كلمات المرور.
- رموز OTP وMFA.
- مفاتيح API والتوكنات.
- رقم بطاقة أو حساب كامل.
- كشف بنكي كامل أو معلومات عميل حساسة.

يوثق GitHub اسم البنك ومرجع المستند وآخر أربع خانات عند الحاجة فقط. الملف الأصلي يرفع إلى مساحة الأدلة داخل التطبيق أو مخزن الملفات المصرح.

## قوالب طلب البيانات حسب المرحلة

### P01 — التسويات

لكل مزود:

- اسم المزود: سلة / تمارا / تابي / إمكان / شركة شحن.
- البنك الحالي لاستقبال التسوية.
- مرجع الحساب أو آخر أربع خانات.
- فترة الكشف.
- رقم/مرجع الكشف.
- الإجمالي قبل الخصومات.
- العمولة قبل الضريبة.
- ضريبة العمولة.
- الاستردادات والإلغاءات والتعديلات.
- صافي التحويل.
- تاريخ وصول البنك.
- المستند الداعم.

### P02 — شركة شحن خارجية

- اسم الشركة.
- نشطة أو متوقفة.
- تكلفة الشحنة قبل الضريبة.
- ضريبة خدمة الشحن.
- دفع مقدم أو آجل.
- البنك الحالي للتسوية.
- شرائح COD: بداية ونهاية وشمول الحدود والنسبة والرسم الثابت وضريبة العمولة.
- تاريخ سريان الإعداد.
- مصدر القيمة: عقد/فاتورة/كشف/تأكيد المالك/نسخ قديم.

### P02 — مندوب متجر

- الموصل الموجود في إدارة الموصلين؛ لا ينشأ شخص مكرر.
- `driver_id` أو السجل المختار.
- سعر التوصيلة.
- تاريخ سريان السعر.
- هل السعر شامل الضريبة أو غير خاضع، حسب الاتفاق الفعلي.
- حالة الموصل.
- أي رصيد COD افتتاحي يؤجل إلى P07 ولا يدخل هنا.

### P03 — فاتورة شراء

- المورد.
- رقم وتاريخ الفاتورة.
- المنتجات والكميات.
- سعر الوحدة والخصم والضريبة.
- المدفوع والمتبقي.
- حساب الدفع.
- تاريخ الاستلام.
- المستند الداعم.

### P04 — حركة مالية

- نوع العملية الفعلية.
- الطرف المقابل.
- المبلغ والتاريخ.
- الحساب البنكي/النقدي.
- المرجع والوصف.
- المرفق.

لا يُطلب من المستخدم العادي اختيار المدين والدائن.

### P05 — راتب أو التزام

- الموظف أو الجهة.
- نوع الاستحقاق.
- الفترة.
- المبلغ الإجمالي.
- السلف والخصومات.
- صافي المستحق.
- تاريخ الاستحقاق والسداد.
- حساب السداد.
- العقد/الكشف/الفاتورة.

### P07 — القطع والأرصدة الافتتاحية

لا يدخل شيء قبل تحديد توقيت قطع واحد. لكل بند يلزم رصيد **عند نفس اللحظة** ومستند مطابق لها. يجب عرض المعاينة الكاملة والمتوازنة ثم الحصول على اعتماد صريح قبل الترحيل.

## نتيجة الجلسة الإلزامية

يجب أن تنتهي كل جلسة بإحدى الحالات:

- `DRAFT_SAVED_AND_REOPEN_VERIFIED`
- `DATA_MISSING_NO_WRITE`
- `VALIDATION_FAILED_NO_POST`
- `POSTED_WITH_EXPLICIT_AUTHORIZATION`
- `BLOCKED_BY_PHASE_GATE`

ولا يجوز إنهاء الجلسة بعبارة عامة مثل «تم» دون تحديد السجلات والحالة الفعلية.
