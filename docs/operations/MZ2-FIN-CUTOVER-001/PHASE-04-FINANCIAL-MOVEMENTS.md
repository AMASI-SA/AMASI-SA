# P04 — الحركات المالية

الحالة: **QUEUED — IMPLEMENTATION_NOT_STARTED / RUNTIME_NOT_ELIGIBLE**

بوابة البناء: **بعد `P03.implementation_status=VERIFIED`**

بوابة Runtime: **ضمن P08 بعد النشر الخامل المتحقق والقيد الافتتاحي و`safe_active=true`**

## الهدف

تنفيذ شاشة واحدة لكل الحركات المالية اليدوية. يختار المستخدم العملية الفعلية ويدخل المبلغ والطرف والحساب والمستند؛ النظام يحدد الحسابات المدينة والدائنة ويعرض المعاينة ثم يحفظ مسودة أو يرحل وفق الصلاحية.

نجاح بوابة تنفيذ P04 يفتح **بناء** P05 دون Publish ودون انتظار
`P03/P04 COMPLETE`. القبول التشغيلي يبقى منفصلًا إلى P08.

## العمليات المشمولة

- تحويل بين حسابين بنكيين أو نقديين.
- إيداع وسحب.
- مصروف عام أو بنكي.
- سداد مورد.
- تحصيل ذمة.
- دفع شركة شحن.
- تسوية COD وفق المسار المتخصص.
- سلفة موظف أو عهدة.
- تسوية موظف أو موصل.
- زيادة أو سحب رأس مال؛ الرصيد الافتتاحي يبقى في P07.
- أي نوع جديد يضاف بعقد حسابات واضح ولا يظهر للموظفين تلقائيًا.

## قاعدة التوجيه

كل نوع عملية يملك قالب قيد ثابتًا وحسابات مسموحة. لا يجوز معاملة كل شيء كتحويل عام.

أمثلة:

| العملية الفعلية | المعالجة |
|---|---|
| بنك إلى بنك | مدين الوجهة، دائن المصدر، بلا إيراد أو مصروف |
| مصروف بنكي | مدين مصروف البنك، دائن البنك |
| سداد مورد | مدين ذمة المورد، دائن البنك |
| تحصيل ذمة | مدين البنك، دائن الذمة |
| سلفة موظف | مدين سلفة/ذمة الموظف، دائن البنك |
| زيادة رأس المال | مدين البنك، دائن حقوق الملكية |

تسويات سلة وBNPL وشركات الشحن لا تمر كتحويل عام؛ تستخدم مسارات P01 وP02.

## مسار الاستخدام

1. اختيار نوع العملية.
2. اختيار الطرف المقابل عند الحاجة.
3. اختيار الحساب المصدر أو الوجهة من القائمة المسموحة لهذا النوع.
4. إدخال المبلغ والتاريخ والمرجع والوصف والمرفق.
5. عرض معاينة مبسطة.
6. حفظ مسودة.
7. مراجعة المحاسب.
8. ترحيل مجموعة قيد واحدة.

## قواعد الصلاحيات

- المستخدم العادي يرى الأنواع والحسابات المسموح بها فقط.
- إنشاء المسودة يحتاج `accounting.drafts.create`.
- القيد اليدوي الاستثنائي يحتاج `accounting.journals.manual_create` ويظل للمحاسب فقط.
- الترحيل حسب نوع العملية يحتاج الصلاحية الحساسة المناسبة.
- الحسابات أو طرق السحب غير المرتبطة بالنوع لا تظهر ولا تقبل عبر API.

## سياسة التعديل

- المسودة قابلة للتعديل مع سجل تدقيق.
- بعد الترحيل لا تعديل ولا حذف.
- التصحيح يتم بعكس القيد في P06 ثم إنشاء عملية صحيحة.
- المرفق والمرجع يبقيان مرتبطين بالعملية الأصلية والعكس.

## البيانات التي يطلبها وكيل المتصفح

- نوع العملية الفعلي.
- التاريخ.
- المبلغ.
- الطرف المقابل إن وجد.
- الحساب المصدر والوجهة المناسبة.
- المرجع والوصف.
- المرفق.

لا يطلب من المالك تحديد المدين والدائن إلا في القيد اليدوي الاستثنائي المخصص للمحاسب.

## متطلبات Backend

- Registry لأنواع العمليات وقوالب القيود.
- operation-to-account bindings وoperation-to-withdrawal-method bindings.
- تحقق tenant وصلاحيات لكل طلب.
- idempotency key لكل عملية.
- حالات `draft`, `reviewed`, `posted`, `reversed`, `rejected`.
- مجموعة قيد متوازنة مع metadata للمصدر والمستخدم والمراجع.
- رأس المجموعة وأرجلها وحالة idempotency والترحيل في
  `accounting_journal_groups_v2` و`accounting_general_ledger_v2` ضمن
  transaction واحدة all-or-nothing.
- كل سجل يحمل `operation_id`، وكل قراءة مالية تقيد بالـtenant والعملية
  ولا تستخدم `current_balance` أو union مع `general_ledger` القديم.
- حاجز `safe_active` يغطي manual/admin/bulk/import/replay وكل endpoint
  بديل قبل أي mutation.
- منع حساب مزود من الاستخدام في تحويل عام إذا كان له مسار تسوية متخصص.
- كشف التكرار والمرجع المكرر.

## متطلبات Frontend

- إجراء رئيسي واحد.
- حقول تتغير حسب نوع العملية.
- قوائم حسابات مفلترة.
- معاينة بلغة مفهومة وأرقام إنجليزية.
- سجل الحركات مع بحث وتصفية بالحالة والنوع والحساب والطرف.
- فتح المرفق والقيد من السجل.

## الاختبارات الإلزامية

- تحويل بنك إلى بنك لا ينشئ إيرادًا أو مصروفًا.
- محاولة تحويل مباشر إلى تمارا/تابي/إمكان تُمنع.
- الحساب غير المرتبط بالنوع يُمنع من الواجهة والـAPI.
- إعادة الإرسال لا تكرر القيد.
- حقن فشل في رجل وسطية لا يترك مجموعة أو أرجلًا جزئية.
- المسودة قابلة للتعديل، والمرحل غير قابل للتعديل.
- المستخدم بلا صلاحية لا يرى أو ينفذ النوع الحساس.
- مجموع المدين يساوي مجموع الدائن لكل عملية.
- كل bypass يرفض قبل mutation عند `safe_active=false`.
- القراءات operation-scoped ولا تستخدم `current_balance` أو
  `general_ledger`.

## سيناريوهات اختبار المتصفح

1. تحويل بين حسابين وحفظ مسودة ثم ترحيل مصرح.
2. تسجيل مصروف عام مع مرفق.
3. تسجيل سداد مورد وربطه بكشف المورد.
4. محاولة اختيار حساب غير مسموح.
5. محاولة تعديل حركة مرحلة والتحقق من المنع.
6. فتح القيد والمرفق من سجل الحركات.

## ممنوع أثناء P04

- إدخال رصيد افتتاحي.
- استخدام حركة عامة بدل تسوية مزود.
- السماح للمستخدم العادي بكتابة أرجل القيد.
- بدء بناء P05 قبل نجاح بوابة تنفيذ P04.
