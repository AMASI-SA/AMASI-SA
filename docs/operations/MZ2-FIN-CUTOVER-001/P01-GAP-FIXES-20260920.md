## التشغيل والصلاحيات

- من صفحة المحاسبة، «الفترات المحاسبية»: اختر الشهر، أدخل السبب ومرجع الاعتماد، ثم إقفال صريح للمالك. إعادة الفتح إجراء مستقل بنفس الصلاحية ونسخة محدثة وسجل تدقيق؛ لا تستعمل تلقائيًا لمعالجة رفض قيد.
- تاريخ الفترات والتقارير Asia/Riyadh؛ الاستحقاق والدفع يستقبلان timestamp مع إزاحة زمنية. لا يمحو تاريخ التدقيق الفعلي.
- «كتابات ميزان2»: إيقاف بسبب موثق ينتظر انتهاء/إلغاء المعاملات الجارية. القراءة متاحة، والأحداث الواردة محفوظة. الاستئناف ثم replay منفصل للمالك. لا حذف سياسة ضريبة أو قطع ولا رجوع للجسر القديم.
- التقرير المؤرخ يحتاج `accounting.journals_reports.view` مع التحقق من صلاحية المستخدم الحالية ومالك بياناته.
- اعتماد استحقاق البيع: `accounting.refunds.recognize`؛ الدفع: `accounting.refunds.pay`؛ لا يستعاض عن الاستحقاق المؤكد بويبهوك يحتاج مراجعة.
- المقدم: `accounting.advances.recognize` للتحصيل و`accounting.advances.refund` للإلغاء والدفع. الصفر الضريبي إدخال صريح يستند إلى مراجعة ومستند، وليس قيمة افتراضية. الحالات الضريبية معلّقة لمراجعة المحاسب بقرار المستخدم. تحصيل مثبت سابقًا أو انتقال المقدم إلى بيع مكتمل يحتاج مسار تسوية مستقل؛ لا يُعاد إثباته.
- Salla/Tamara/Emkan: استرداد العميل لا يعكس رسومها أو ضريبتها آليًا. تابي: مبالغ الرد الفعلية الموثقة فقط، بلا نسبة مفترضة.

جاهزية قاعدة Production ومعاملاتها وفهارس التفرد والنسخ الاحتياطي والاستعادة المعزولة غير متحققة. المطلوب صفحة **Manage Publishing** لمشروع **Salla Analytics** لإثبات ربط الإنتاج، ثم صفحة **Cluster / Indexes / Backups / Restore** لمزود قاعدة Production الفعلي؛ اسم المزود والـcluster والرابط المؤكد لم يتوفرا. وجود ملف نسخة أو نجاح Replica Preview لا يثبت الاستعادة أو جاهزية Production.
