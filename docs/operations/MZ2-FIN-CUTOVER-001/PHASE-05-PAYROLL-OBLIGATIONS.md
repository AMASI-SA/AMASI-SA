# P05 — الرواتب والالتزامات

الحالة: **BLOCKED_BY_P04**  
بوابة الخروج: **LOCKED**

## الهدف

تنفيذ صفحة واحدة للرواتب والسلف والعهد والالتزامات الدورية، تفصل بين استحقاق المصروف وسداده، وتحافظ على ذمة مستقلة لكل موظف أو جهة.

## النطاق

- إعداد راتب الموظف وتاريخ السريان.
- احتساب استحقاق الفترة.
- البدلات والخصومات.
- السلف والعهد.
- سداد الراتب كاملًا أو جزئيًا.
- الالتزامات الدورية مثل الإيجار والخدمات والعقود السنوية.
- ربط الحساب البنكي أو النقدي عند السداد.
- مسودة، مراجعة، ترحيل، مرفقات، وسجل تدقيق.

## هوية الموظف

- يستخدم النظام سجل الموظف الموجود في إدارة الموظفين؛ لا ينشئ موظفًا ماليًا مكررًا.
- كل موظف له ذمم مستقلة للراتب والسلفة والعهدة.
- إذا كان الموظف أيضًا موصل متجر، تبقى أجرة التوصيل وCOD في P02 منفصلين عن راتبه وسلفه.
- لا تتم مقاصة راتب موظف أو عهدته مع موظف آخر.

## سياسة المصدر القديم

يسمح بنسخ اسم الموظف والراتب الحالي أو اسم الالتزام وتكراره كإعداد غير معتمد، ثم يراجعه المالك. يمنع نسخ:

- راتب تاريخي إجمالي.
- رصيد مستحق قديم.
- سلفة أو عهدة أو خصم غير مثبت.
- رصيد افتتاحي لموظف أو جهة.

الرصيد المستحق عند القطع يدخل في P07 فقط وفق عقد وكشف دفع أو إقرار معتمد.

## تصميم الصفحة

### التبويب 1 — الرواتب

لكل موظف:

- الراتب الأساسي.
- البدلات.
- تاريخ السريان.
- دورة الاستحقاق.
- الاستحقاق الحالي.
- المدفوع والمتبقي.
- السلف والخصومات.
- المرفقات.

الإجراء الرئيسي حسب الحالة: إنشاء استحقاق، مراجعة، أو سداد.

### التبويب 2 — السلف والعهد

- إنشاء سلفة أو عهدة مرتبطة بالموظف.
- تحديد الحساب المصدر.
- متابعة الرصيد المتبقي.
- تسجيل استرداد أو خصم مصرح.
- منع حذف عملية مرحلة.

### التبويب 3 — الالتزامات الدورية

- اسم الجهة أو الالتزام.
- النوع.
- مبلغ وتكرار الاستحقاق.
- تاريخ البداية والنهاية.
- حساب المصروف والذمة.
- تاريخ الاستحقاق التالي.
- السداد والمرفق.

## المعالجة المحاسبية

### استحقاق راتب

- مدين: مصروف الرواتب والبدلات المعتمدة.
- دائن: رواتب مستحقة لكل موظف.

### سداد راتب

- مدين: راتب الموظف المستحق.
- دائن: البنك أو الصندوق.

### صرف سلفة

- مدين: سلفة الموظف.
- دائن: البنك أو الصندوق.

### التزام دوري

- عند الاستحقاق: مصروف مقابل ذمة الجهة.
- عند السداد: تخفيض الذمة مقابل البنك أو الصندوق.

لا يجوز دمج الاستحقاق والسداد في حركة واحدة إذا وقعا في تاريخين مختلفين.

## البيانات التي يطلبها وكيل المتصفح

### الموظف

1. اختيار الموظف الموجود.
2. الراتب الأساسي والبدلات.
3. تاريخ السريان ودورة الاستحقاق.
4. أي خصم أو سلفة مثبتة للفترة.
5. تاريخ ومبلغ السداد.
6. حساب السداد.
7. العقد أو كشف الراتب عند الحاجة.

### الالتزام الدوري

1. اسم الجهة والنوع.
2. المبلغ والتكرار.
3. تاريخ البداية والنهاية.
4. تاريخ الاستحقاق.
5. حساب السداد.
6. العقد أو الفاتورة.

لا يدخل الرصيد المستحق قبل القطع في هذه المرحلة.

## متطلبات Backend

- ربط مالي بهوية الموظف الحالية.
- تاريخ إعدادات الراتب وعدم إعادة كتابة الفترات القديمة.
- حالات دورة الراتب: `draft`, `accrued`, `partially_paid`, `paid`, `reversed`.
- idempotency لكل فترة موظف ولكل عملية سداد.
- منع إنشاء استحقاقين لنفس الموظف والفترة دون تصحيح رسمي.
- ذمم منفصلة للراتب والسلفة والعهدة.
- إنشاء التزامات دورية مرة واحدة لكل فترة مستحقة.
- صلاحية `accounting.payroll.post` للترحيل.
- سجل تدقيق ومرفقات.

## متطلبات Frontend

- بطاقات موظفين مبسطة.
- عرض الراتب، المستحق، المدفوع، المتبقي، والسلف بأرقام إنجليزية.
- حفظ مسودة للمستخدم العادي.
- مراجعة وترحيل للمحاسب.
- فلترة حسب الفترة والحالة والموظف.
- فتح كشف الموظف والقيد والمرفق.

## الاختبارات الإلزامية

- استحقاق الفترة لا يتكرر.
- السداد الجزئي يبقي المتبقي صحيحًا.
- تغيير راتب لاحق لا يغير فترات مرحلة.
- السلفة لا تعامل كمصروف راتب.
- أجرة موصل المتجر لا تختلط بالراتب.
- الالتزام الدوري لا يتكرر لنفس الفترة.
- المستخدم بلا صلاحية ترحيل يفشل من الواجهة والـAPI.
- القيد متوازن وidempotent.

## سيناريوهات اختبار المتصفح

1. نسخ راتب كمسودة ثم اعتماد المالك له كتكوين جديد.
2. إنشاء استحقاق موظف وحفظه ثم ترحيله.
3. سداد جزئي ثم إكمال السداد.
4. صرف سلفة ثم تسجيل استرداد.
5. إنشاء التزام دوري والتحقق من عدم تكراره.
6. فتح كشف الموظف والجهة والقيود.
