EXIT-2D future cutover/restore runbook — NO Production actions authorized now

Old-owner stop proof is a mandatory gate, not MEZAN_LEGACY_WORKERS_STOPPED=1.
The old mixed server does not understand independent-role leases. Running both
versions on the same provider credentials/database can duplicate writes even if
new-worker role claims are exclusive. Do not route a canary worker to Production.

Ownership transfer, after separate approval
  0. Freeze reviewed source, callbacks and all28 proposed ownership entries.
     Reconcile static inventory with live registration and launch flags. Six
     callback families previously observed; supplier scan/taxonomy remain explicit
     registration gaps until exercised. Include all direct Salla/Qoyod/shipping
     tasks, outboxes, operational balances, subprocess schedulers and HTTP writes.
  1. Schedule a short write-maintenance window. Stop interactive financial,
     advertising, shipping and Salla mutations as well as background producers.
     Persist incoming provider events to one durable owner/inbox or request
     provider retry; do not ACK and discard, and do not change webhooks now.
     Block execution, retain event IDs and current provider retry metadata.
  2. Disable old automatic restarts, scheduled jobs, scale-up, deploy hooks and
     build-repair automation. Enumerate ALL old replicas/process trees, detached
     provider subprocesses, cron and external schedulers. Record hosting-service
     and instance IDs, exact source/boot IDs, PIDs/children and stop timestamps.
  3. Drain old work. Classify each in-flight action as confirmed-success,
     confirmed-not-sent or outcome-unknown. Never treat network timeout as failure.
     Qoyod invoice/Salla shipment or status actions with unknown outcomes require
     read-back/reconciliation against their existing business/idempotency IDs;
     no blind replay, no new invoice IDs or changed finance/invoice rules.
  4. Required independently retained evidence, before arming ANY new writer:
       - supervisor/provider control-plane confirms desired AND running replicas0;
       - restarts/autoscaling/cron disabled; no old process/container children;
       - bounded drain completion or explicit unknown-outcome quarantine;
       - no renewing old startup/job leases and no advancing dispatch checkpoints
         across at least max(all observed lease TTLs, provider request deadlines,
         subprocess kill grace) plus clock-skew allowance; do not assume15s covers
         every historic job just because the new role lease uses15s;
       - Mongo ledger/inbox/outbox counts, last event/provider IDs, write barrier
         timestamp and last committed opTime; no active old producer;
       - protected evidence receipt, exact SHA256 of control-plane exports,
         reviewer, old/new source IDs and domain-by-domain owner map.
     No certificate is generated by this task and no old owner has been stopped.
     Missing evidence means STOP. A flag or absence of one log line is insufficient.
  5. After a consistent final data barrier, restore/synchronize target, verify
     schema and persisted dedupe/inbox/checkpoints. Start new Web with writers
     unarmed, then reports. Check employee auth/session/RBAC and operational views.
  6. Arm exactly one new domain at a time under its role lease: sync first only
     after all its domains transferred; accounting only after Qoyod ledger proof.
     Existing broad sync role owns shipping/payment/review loops together; do not
     claim individual provider canaries unless their existing enable flags safely
     isolate them. No provider features are enabled just to test worker execution.
  7. Traffic progression/readiness must never create two write owners. During
     gradual Web traffic transfer, old mutating endpoints remain blocked until
     cutover complete. For zero-write canaries use the isolated synthetic dataset.
     Validate provider read-back, dedupe IDs, unique indexes and backlog progress
     before widening writes. Observe unknown-outcome queues without auto-replay.
  8. Rollback is another ownership transfer: disable NEW producers, drain/kill and
     prove all new owners stopped, reconcile any new writes, synchronize them to
     old storage if needed, then explicitly rearm old owner. Never simply start
     old workers against a stale backup after new writes occurred. If rollback
     data cannot be reconciled, keep writers stopped and repair forward.
  9. Production artifact/merge/publish requires separate authorization and all
     existing V5 gates. No Production lease is prepared by this branch/task.

Backup/restore plan, before any real export
  A. With separate read authorization, establish actual Mongo owner/topology,
     server+FCV/tools versions, replica-set/sharded status, backup/PITR authority,
     collection/index/size metadata, encryption key custodians and all file stores.
     No topology, Atlas subscription, backup ID or RPO/RTO is inferred here.
  B. Prefer consistent managed snapshot/PITR to an isolated target. If database
     tools are used, pin compatible tools and use a verified consistency method.
     mongodump --oplog requires a full supported replica-set dump; it is not a
     generic --db/--collection/sharded consistency flag. A dump does not include
     later writes. Use verified CDC and final barrier or stop writers and take
     the final consistent backup. Preserve replica/app transaction assumptions.
  C. Export includes all _id/business IDs, unique/TTL indexes, counters, ledger,
     provider aliases, invoice mappings, inbox/outbox IDs, leases/checkpoints,
     dedupe receipts, pending/unknown outcomes, review/preparation histories,
     binary Mongo media/GridFS if present. Do not omit encrypted config collections.
     Expired role leases are reviewed, never mass-deleted as a restore shortcut.
  D. Keys: preserve exact primary and retained old encryption keys with their
     version IDs and independent recovery copy. Inventory SALLA_TOKEN_ENC_KEY,
     Qoyod/OAuth encryption dependencies, JWT-derived MFA/session encryption and
     any old-key/fallback configuration from actual source/config names. Preserve
     signing/session keys if sessions must survive. Never rotate while relocating.
     Hosting secret manager receives values through approved secure channels,
     not Git, tickets, CI artifacts, shell history or chat. Record names/versions
     and success/failure only, never plaintext, ciphertext samples or key hashes
     that violate the organization's secret-handling policy.
  E. Files: inventory backend/uploads and every runtime file path, provider PDFs,
     attachment receipts, logos/fonts, object buckets and Mongo Binary fields.
     mezan_product_media_uploads_v2 contains Binary data with7-day TTL; directory
     copying cannot replace its backup. Produce encrypted manifests with path,
     length and checksum, preserving access control and references. No shared
     multi-service application files are placed on Render's single-service disk.
     Use a separately approved object-store adapter/migration for durable shared
     files; until inventoried and accepted this remains a Production blocker.
  F. Verify backup checksum/completion/readability BEFORE cutover. Restore into
     a new isolated target with no real provider egress and workers disabled.
     Compare collection counts, deterministic ID sets/digests, index specs, last
     opTime/barrier and ledger totals. Decrypt representative tokens/MFA/records
     in memory without provider calls/log output. Read attachment bytes and verify
     stored checksums/MIME/ownership. Check unknown outcomes and inbox continuity.
     Never make a financial write to prove a key works.
  G. Measure backup/restore duration to set actual RPO/RTO; require a timed second
     restore, written reconciliation and retained encrypted backup before approval.
     Keep source intact until approved retention expires. A synthetic dump/restore
     test proves harness mechanics, not recoverability of current Production.
