منهج الاختبار:
Ubuntu24.04/Docker، الصور الفعلية للواجهة/Nginx/الخدمات/Mongo، شبكة داخلية بلا
منافذ منشورة، قاعدة اصطناعية ثابتة وأسرار عامة للاختبار فقط. لا اتصال بمزودي
الخدمات الحقيقيين أو ببيانات/أسرار الإنتاج. CPU/RAM لكل خدمة مطابق للمرشح؛
تعطيل swap صراحةً. Migration منفصل محدود1CPU/2GB؛ موارد بناء الصورة ليست
موارد تشغيل الخدمات، وRender يحتسب دقائق البناء منفصلة وفق خطة Starter.
قرص ext4 اصطناعي داخل ملف محدود إلى5,000,000,000byte، لا tmpfs لبيانات Mongo.
مراقبة cgroups من المضيف بلا إضافة عمليات رصد داخل الخدمات. تشمل كل العمليات
التابعة، الذاكرة الحالية/الذروة والمتوسط وworking set وanonymous وOOM/cpu.stat.
ذاكرة file cache القابلة للاسترداد تُعرض منفصلة عن دلالة ضغط الذاكرة؛ وصول
الإجمالي إلى الحد لا يعني تلقائيًا حدوث OOM. تبقى الأحداث والذروة الخام محفوظة.

تسجيل الدخول يستخدم التحقق الحقيقي من كلمة المرور وMFA/OTP؛ لا رموز جلسة مصطنعة.
حمل سناب: نفس حاوية Sync وتشترك معها مواردها، عملية إضافية تحفظ وتكرر مزامنة
100 حملة و2400 حقيقة ساعية عبر عميل سناب الحقيقي وMongo الحقيقي وlease حقيقية.
محاكي النقل HTTP داخل الذاكرة فقط؛ لا OAuth أو حساب سناب حقيقي. هذه تجربة

وبعدها؛ النتيجة المطلوبةalready_sent والبيانات بلا تغيير. تُحتفظ اختبارات
المنطق المالي السابقة للمسارات الأخرى؛ لا إرسال فاتورة حقيقية أو تغيير ضوابط.
تُختبر محاولة بدء مالك Worker ثانٍ والرفض، وسقوط التقارير/المزامنات/المحاسبة
واستمرار الموظفين، ثم إعادة تشغيلها وإيقافها المنظم، وإعادة تشغيل Web أيضًا.
تُقاس مساحة Mongo والفهارس قبل الحمل وبعده وبعد إضافة50MiB ملفات عشوائية لا
تُضغط بسهولة. هذا يثبت كفاية الحِمل المحدد فقط، وليس نمو قاعدة الإنتاج.
