## Six policy write hooks

All six route handlers are actually attached by `google_ads_routes.attach_google_ads_management_routes`; these are relative to the existing integrations router prefix. Each mutation calls `mutate_google_automation_policy -> probe_google_budget_guard_transactions -> GuardedGooglePolicyWriter -> PolicyMutation -> common transaction/epoch`. No legacy nontransaction fallback exists.

| Route | OAuth dependency before mutation | Current gate |
| --- | --- | --- |
| PUT `/google_ads/automation/policy/{account_id}` | Linked account and live account metadata read required. | Unique policy index creation plus supported common TX. |
| POST same path `/revoke` | **None.** Persisted owner authentication and normalized local account identifier only. | Supported common TX; no runtime execution flag required. |
| POST same path `/activate` | Linked account and current native metadata plus explicit owner activation required. | Runtime unavailable by default; no automatic activation. |
| PUT `/google_ads/automation/creation-policy/{account_id}` | Linked account/native metadata/geography and current product/template proof. | Existing save validations/index plus supported common TX. |
| POST same path `/revoke` | **None.** Persisted owner authentication and local normalized scope only. | Supported common TX; no creation runtime flag required. |
| POST same path `/activate` | Current linked account/native/catalog/template proof and owner activation. | Runtime unavailable by default; PAUSED-only contract. |

OAuth independence is conditional on healthy authenticated application/Mongo access and supported transactions. The technical engine probe does not inspect OAuth and does not prove business namespace permissions. Unsupported/unknown transaction capability fails closed with no fallback; migrating handlers before actual business permission/index/legacy proof could therefore disable existing saves and revocation. This remains a deployment blocker, not a request for owner approval. No route permission or runtime flag was changed by this audit.

## Concrete remaining blocker and smallest next code patch

A counterexample exists for standing `set_budget` after a future runtime enablement: the guarded reservation commits, an owner revokes through the common epoch, then the old proposal-only standing submission CAS still succeeds because it does not read or write that epoch/current policy. Its global execution flag and native age can remain valid. Likewise policy expiry can cross the floor while native proof is younger than 90 seconds. The creation-only fix does not cover this path. All runtime is currently disabled, so this is a rollout blocker, not evidence of a present funded dispatch.

Smallest next patch: introduce a separate typed `StandingDispatchFloor` command, with exclusive ownership of a narrow `automation.kind == standing_policy` native-floor seam. In the mandatory common TX reload and bind current enabled policy/revision/digest/activation/expiry, exact `_dispatch_claim`, reserved standing allocation/resource/lineage/amount, immutable original proposal/analysis/operations binding and native fence. Write submission marker and common epoch in the same one-attempt raw commit. Carry validity bounds only from stored policy/proposal; check fresh time before commit and synchronously after positive ACK. A revoke first blocks HTTP; an ACKed floor first is explicitly in flight; unknown ACK retains allocation/fence with no HTTP, refund or replay. Keep pause/known settlement behavior and creation floor unchanged. Do not restore enable/resume provenance, fund first launch or enable runtime in that patch.

Acceptance: independent real clients must race revoke versus guard epoch and owner cancellation versus proposal write; positive floor before revoke must be distinguished from revoke first. Add policy expiry while waiting/before commit/during ACK; exact original resource/budget/claim tampering; failCommand commit91/connection-close and positive-commit response loss, exact one wire attempt, retained holds/fence, no provider call on unknown; fresh client/restart and readback must never reuse a consumed receipt. Preserve current retail/CAS/automatic resume denial and all six OAuth-independent revocation tests.

Separately, shared owner/product/OAuth metadata writers and external Google writers remain unserialized after the last read. A read snapshot or immediate revalidation is not a common writer fence. Any future requirement to eliminate those races needs an explicitly designed shared writer epoch/CAS contract, not a claim that the budget transaction already solved it. Production commit/namespace/legacy/native inventory proof remains prerequisite before six-handler migration; a positive abort-only or generic commit technical diagnostic alone is insufficient.
