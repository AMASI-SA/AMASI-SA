# حدود تغطية ضابط الكتابة R6.1

هذا جرد للنقاط المرتبطة واختباراتها، وليس شهادة أن كل عملية على الإنتاج تمر بها.
الحالة: ضابط موجود ومختبر معزولًا؛ إيقاف البيئة الحية وهدف الرجوع غير مقبولين.

| المدخل | الربط/الحماية | الدليل |
| --- | --- | --- |
| إنشاء الطلب المحلي | creation+workflow في transaction واحدة | missing/paused يمنع الإنشاء ولا يخفي الموجود |
| تحديث الطلب وإيصالاته | workflow+evidence | إنشاء مغلق مع قراءة/معالجة الموجود ممكنة حسب بقية النطاقات |
| التحصيل والتكلفة والقيود | financial مع workflow/evidence عند الحاجة، وrequire_admitted لدى مالك القيد | native bank/COD/supplier/inventory/settlement + rollback/replay |
| إعدادات وسياسات/FX/صلاحيات الميزة | configuration وصلاحية محفوظة حديثة | paused يرفض إعدادات جديدة |
| الأدلة | evidence داخل معاملة، الملف محفوظ خاصًا | paused upload/attestation مع قراءة الدليل القديم |
| طابور الإشعارات المحلي | dispatch، وبقية النطاقات التي يحتاجها المستهلك | لا ادعاء مصالحة أثر خارجي غير معلوم |
| مسارات native المحلية/المختلطة | wrapper محافظ يتطلب workflow+financial+evidence | توقف المالية قد يوقف native workflow أكثر من الضروري؛ ليس وعدًا بتجزئة دقيقة لكل زر |
| إغلاق فاتورة المورد | إعادة استعمال جلسة المعاملة المسموحة لا جلسة مستقلة | فاتورة مختلطة ترفض كاملة عند الإيقاف؛ المسار الإيجابي ينجح |
| إعادة محاولة رفع ملف | snapshot محدود ثم stream جديد لكل callback | اختبار handler يغلق الملف ثم يعاد دون بايتات ناقصة |
| التحكم نفسه | مالك محفوظ، paused-only init، revision/epoch وaudit | صلاحية مسحوبة، إعادة نفس المفتاح، أول تهيئة متزامنة، تاريخ بلا ضبط |
| طرق التعديل غير المباشرة | منع delete وdrop و$out/$merge؛ R6.1 يمنع bulk_write أيضًا | أربع حالات فشلت على R6 ثم نجحت بعد المنع |

## الحد المثبت

كل كاتب مرتبط يعدل سجل تحكم المتجر في نفس transaction قبل كتابة العمل. معاملة المالك لتغيير النطاق تعدل السجل نفسه، فتتعارض مع المعاملة السابقة أو تنتظرها. بعد نجاح الإيقاف لا يسمح كاتب مرتبط بجيل/ضبط قديم بإكمال كتابة جديدة. القراءة تبقى متاحة. اختبرت حالات سباق حقيقية على Mongo وحالة callback retry مصطنعة موثقة؛ لا نخلط بينهما.

لا يكفي استدعاء الدالة من خارج المعاملة أو اختيار نطاق بلا tenant؛ ذلك ممنوع. الغلاف ليس بديلًا لصلاحيات Mongo، ولا يعترض الكتابات إلى الجداول العادية خارج المسار المحلي. لا يمكنه إيقاف برنامج يمسك raw_database ويكتب مباشرة. لا توجد في هذه الجولة هوية كل worker في الإنتاج أو acknowledgments منهم.

## ما يزال يلزم قبل قبول الرجوع

جرد واختبار APIs/jobs/webhooks/queues/cron والأجهزة القديمة، اختيار الفواتير والدفعات المختلطة بين القراءة والكتابة، جميع الكتّاب إلى الجداول المشتركة، والآثار البنكية/الشحنية ذات النتيجة غير المعروفة. يجب حفظ القدرة على القراءة عبر كل النسخ الداعمة. اختبار الضغط مهم لأن سجل التحكم يسلسل العمليات المرتبطة لكل متجر؛ timeout ليس إيقافًا ناجحًا.

غياب ضبط الميزة مع معاملات موجودة لا يعالج بإنشائه تلقائيًا. بعد وجود سجل audit مع ضبط مفقود، المسار يحجب initialization ويحتاج مصالحة إدارية موثقة. static Enablement يبقى حدًا أعلى ولا يتغير بأي طلب التحكم. لا API route مفعلة في server.py في هذه الجولة.

لا يستنتج الفاحص offline اكتمال هذا الجرد من نجاح38 حالة تحكم أو من CI. تقرير الرجوع يجب أن يتضمن ضبط الكتابة وتدقيقه ضمن17 سطحًا، ونسخة رجوع متوافقة، واستعادة backup معزولة ومراجعة مستقلة. أي دليل مجهول يبقي النشر/الرجوع محجوبًا.
