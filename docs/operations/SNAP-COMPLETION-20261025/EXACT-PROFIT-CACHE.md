# Exact campaign profitability cache inputs

Base: production `72ab1aee0fa9520b3a5f91f924906a3be3337531`. The existing adapter reuses exact locally matched Salla orders and current selected-account campaign spend. Its five-minute cache was keyed only by owner, date range and product-cost revision. A new order, changed amount or line quantity, removed/reassigned order, or changed Snapchat spend could therefore return the previous cohort's economics until expiry.

The key now also binds a process-local SHA256 digest of the actual matched order documents, their account/campaign associations and selected campaign spend. Full order documents are included because the existing cost helpers consume multiple aliases, status and refund fields; this avoids a second incomplete dependency list. Record order is ignored while duplicates remain part of the input multiset. Inputs that cannot be serialized safely bypass caching. No customer fields, hashes or payloads are logged or persisted. Existing cost-revision invalidation, TTL, entry bound and defensive result copies remain.

Fresh baseline reproduction: five focused regressions failed on the unchanged implementation, proving stale sales, cost, order count and spend for modified inputs. After correction, **33 tests passed**, exit 0, covering exact reuse, campaign profitability, current catalog cost, result-source and created-order semantics. Additional checks cover changed account/campaign scope, unchanged/reordered cache hits, detached result mutation and cache bypass for unsafe serialization. Existing workflow `prod-campaign-profitability-exact-reuse-v2.yml` already triggers on these source/test paths and selects the exact-match suite; no workflow change is needed or included.

This is a local cache-correctness fix, not an upstream Salla freshness certificate. The product-cost revision is durable in Mongo with `updated_at`, but does not certify order-import coverage. Current Salla range logs omit the exact filter/store/calculator provenance; auto-sync's process-local last-success value can advance after per-order failures; V3 synchronization state is explicitly shadow-only. Completing that upstream contract still requires authoritative tenant/store/range coverage and committed cohort/cost revision bindings. The Snapchat scale gate must remain fail-closed until those facts are available and validated. This patch does not synthesize a timestamp, change that gate, promote shadow data, or write to providers, accounting or Qoyod.

Production unchanged. Root owns review, integration and governed publication.
