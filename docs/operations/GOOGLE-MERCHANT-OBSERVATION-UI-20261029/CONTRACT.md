# Explicit owner Merchant observation panel (unattached)

Parent is frozen reviewed owner route `69919f5045ec399492f391cef844cc97af005432`.
No parent component, workspace, service, backend, router or release intent changes.
Root owns fresh production integration and actual route/component attachment.

`GoogleMerchantObservation` takes `isOwner`, `ownerId`, `accountId`, `merchantId`.
Integration supplies the authenticated owner identity and account IDs explicitly
chosen by the owner from observed owned accounts; it must not infer a Merchant,
silently choose the first account, or reuse an implicit configured default.
These props control presentation and request scope, not backend authorization.
Without valid explicit selections no button/read exists; non-owner view is hidden.

Only a manual button sends one fixed existing `lib/api` GET with explicit IDs,
AbortController signal and a finite timeout. The existing `_mezanAuthRetried:true`
contract disables browser-session refresh POST/automatic GET replay for this
request. No tokens are read or supplied by the component. A test exercises the
actual existing API interceptor using a synthetic adapter, proving a401 causes
one GET attempt and no refresh POST. No mount, poll, expansion, pagination,
selection-change or cancellation action reads/saves/syncs provider data.

Changing owner/account/Merchant or leaving owner mode unmounts the scoped panel,
aborts the request and removes old evidence immediately. Generation and active
scope checks ignore late responses even when a transport ignores cancellation.
Explicit retry clears prior evidence; cancellation cannot let an old request
clear or replace a newer request's state.

The consumer validates scope, complete traversal, exact native product identities,
duplicates, data-source ownership, link evidence and every non-authorizing flag.
It shows Merchant/offer/language/feed/local-or-standard identities separately;
standard is not verified Google Ads ONLINE channel. Archived does not become
inventory or eligibility. Distinct product/mobile/canonical/ads redirect URLs are
rendered only as inert text. Opening details or paging25 rows uses the already
read result and triggers no GET or URL fetch. All rows are validated before paging.

The positive fixture was generated by the actual parent route and reviewed
observer's `as_public_dict()` with the existing synthetic Python test providers;
it is not invented schema or live Google evidence. It preserves source, digest,
full identity, explicit false flags and access observations exactly. The frontend
does not verify the digest cryptographically or accept it as future authority.

Visible limits: store/feed matching remains unverified; no stock, Google Ads
eligibility, destination, section membership, sales attribution or execution
claim. Bracketing reads do not prove uninterrupted state. Empty results describe
only the selected Merchant read and never imply an empty Salla store.

Acceptance: explicit scope/no defaults; no initial requests or writes; actual API
no-refresh/no-replay behavior; current server fixture; complete empty result;
all-row/native identity refusal; role/owner/account/Merchant changes; abort ignored
and late completions; manual retry/cancel/unmount; safe errors and inert URLs;
local pagination/expansion; governed frontend tests and build; independent review.
