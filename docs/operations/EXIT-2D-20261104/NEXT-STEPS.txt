ترتيب التنفيذ التالي — كل خطوة على المصدر الحالي وباختبارها، بلا backport أعمال سبتمبر
1) حزمة bootstrap/security:
   أعد استخدام فكرة فصل تثبيت middleware عن ensure_indexes من سبتمبر، لكن ابدأ بمثبتات الإنتاج الحالية. الحفاظ على default behavior ومخطط وترتيب mobile/progressive/login/passkey/MFA/email OTP وmeta reviewer إلزامي. تثبيت middleware عملية محلية لكل replica؛ الفهرسة migration منفصلة. profile Mongo يجب أن يثبت صفر lifecycle writes في web بعد الفصل، مع السماح بكتابات الطلبات المشروعة.
   بوابة قبول: denial قبل الجاهزية، cross-process login/refresh/revocation، review-session authority، MFA/passkey/OTP contracts، وتعطل Mongo -> 503 دون logout كاذب. لا تعديل خوارزمية الفواتير.
2) تكييف migration/readiness:
   bounded Mongo probe الحديثة مع schema marker وهوية artifact مراجعة. migration_fail -> no ready؛ retry/idempotence؛ لا seed إلا قاعدة خالية وشروط الإنشاء الحالية، دون مسح أو backfill تلقائي. راجع import-time writes صراحة.
3) role registry/runtime:
   exact callbacks مع start/stop مقابل role، no unknown callbacks، حفظ settings/flags المعطلة. per-role readiness وleases ثابتة عبر source versions، مع جسر انتقال يحجب legacy worker عند بدء roles. كل provider/accounting side effect ما زال محكومًا بالعقود الحالية، لا task lease وحدها.
   بوابة قبول: عامل لا يستطيع بدء عائلة أخرى؛ lease loser لا يعمل؛ fence loss يوقف التنفيذ؛ drain deadline ثم supervisor kill؛ عدم إحياء task/subprocess بعد shutdown؛ النتيجة المجهولة لا تعاد بلا مصالحة.
4) تقارير + قبول كامل:
   طابور/جدولة دائمة وإظهار freshness، مع مطابقة النتائج القديمة وRBAC/tenant separation وحدود الذاكرة والتزامن؛ ثم EXIT-2C/2D على Linux مع synthetic providers قبل أي نسخة حقيقية. أعد استخدام اختبارات سبتمبر بدل استبدالها باختبارات شكلية.
لا تُعدّ أي خطوة من هذه الأربع منفذة في هذه المرحلة.

حدود أدوات الجرد
لا control-flow أو import graph كامل، لا resolve للـaliases/custom task factories، ولا إثبات لعدد callbacks النهائي أو قيمة flags الحية. استدعاءات add_event_handler تظهر مرشحين تحتاج مراجعة. runtime callback inventory المعزولة شرط قبول لاحق مستقل.
لا يُستخرج argument literal أو env value. أخطاء parse تعيد نوع الخطأ والمسار فقط. فحص الخطة يرفض hook جديدًا أو مجهولًا، owner مكررًا/غير معروف، مدخلًا قديمًا أو تغير البصمات. لا تُستخدم الخطة للتنفيذ أو منح صلاحيات.

تحقق هذه المرحلة
8 اختبارات جديدة للأداة: لا تنفيذ للمصدر، عدم إخراج literals، decorated/append callbacks وnested scopes، dynamic hook unresolved، syntax error مصنف دون مصدر، source drift، unknown/new hook، duplicate/invalid ownership.
كلها نجحت محليًا على Python 3.13؛ فحص role-plan نجح. لا Docker أو dependencies أو CI جديد. الاختبارات الجديدة تثبت سلوك أداة التحليل فقط.
