# Cash-only card and custody settlement follow-up

Supersedes the cash card interaction in CASH_CARDS_20261007.md. Cashbox card now
selects a cashbox followed by supplier/employee cash payment. Its source is fixed
to that cashbox; no bank selector or bank-transfer operation in this card.
Existing operational transfer API and historical retry compatibility are retained.

Custody card selects an employee custody then offers supplier payment or return
to an assigned cashbox. Supplier payment uses the existing allocation/payment
engine, reduces custody and supplier outstanding, and never debits a bank.
Cash return reduces custody and increases cash without an expense. Native custody
IDs are restricted to the MZ2 employee whose account_user_id matches the actor;
the owner sees all. Missing/ambiguous account links fail closed. This is rechecked
at the existing persistence authorization boundary. Browser membership unchanged.

Inventory settlement is NOT implemented/accepted. Investigation found the
existing purchase_receiving_service._validate_posting requires active accounting
and its approval transaction invokes post_journal_v2. It creates G47 purchase
receipts, an accounting supplier liability, and capitalization costs with tax
treatment. No independent custody-funded inventory settlement contract was found.
Calling this flow or treating capitalized cost as cash paid would cross the
authorized operational-only boundary. UI explains unavailability and no posting
shortcut is exposed. Next decision: define/read an independent operational
inventory receipt/value/payment linkage with ownership and duplicate prevention.
No purchase/stock/accounting source was modified or invoked.
