## المضيف والنسخة

تم الوصول إلى طرفية المضيف الأصلي المأذون به. هناك نُفّذ أمر القراءة فقط:

```bash
cd /app && python3 -B scripts/production_release_guard.py status
```

كانت الاستجابة الفعلية **`{"active": false}`** وقت القراءة. كان رأس مساحة المضيف **J2 `7d1be020b9559ea294b6ea3f7511f37ee5e6a847`**، بلا تغييرات على الملفات المتتبعة. تُركت الملفات غير المتتبعة كما هي. قورنت مسارات التغيير الـ137 بين النسختين: لم يوجد عند الفحص أي تعارض بينها وبين الملفات أو مسارات الملفات غير المتتبعة الموجودة مسبقًا. لم يُنفَّذ حذف أو تبديل نسخة في مساحة المضيف. هذه قراءة لحالة الحجز وقتها، وليست إنشاء حجز أو ضمانًا لبقائه غير نشط.

بُنيت المعاينة من نسخة منفصلة ومؤقتة مطابقة لـ **B2 `4b7eed3b40aae718a6652486010342c9d3701261`** باستخدام Node **22.23.2**. استُخدم مكوّن التقرير ومولّد البيانات الاصطناعية الحقيقيان من المرشح. اقتصر تكييف المعاينة على بادئة مسار النقل اللازمة لبروكسي المحرر. نجح البناء ولم تتغير ملفات المصدر المتتبعة. لا وصول إلى سجلات المتجر أو كتابة مالية ضمن هذه المعاينة.

## المتبقي قبل الدمج

1. على المعاينة الاصطناعية نفسها مع فلتر التحويل البنكي، يتولى المالك التحكم للضغط على **طباعة التقرير** ثم **حفظ بتنسيق PDF** في نافذة الطباعة الأصلية. افتح الملف الفعلي وراجع العربية والمبالغ غير المقصوصة، وهوية الطلب المحدد، وعدم دخول أزرار أو محتوى خارج التقرير في الصفحات. يُسجَّل ما شوهد فقط.
2. بعد القبول، أعد قراءة حالة حجز المضيف ورأس فرع الإنتاج الفعلي. إذا تغير أيٌّ منهما، افحص التغيير أو نسّق الحجز قبل المتابعة. لا تُزل حجزًا تابعًا لعمل آخر.
3. إذا بقي المرشح صالحًا، تابع الدمج المضبوط لـ #1702 برأس B2 المتوقع وشجرة مطابقة، ثم خطوات النشر والتحقق الحي وفق v5. المعاينة لا توافق على فروق فواتير أو مدفوعات أو رواتب حقيقية.
