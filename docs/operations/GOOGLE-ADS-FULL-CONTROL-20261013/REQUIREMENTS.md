# Google Ads داخل ميزان — عقد إنشاء وإدارة الحملات للمسوّق والذكاء

Task: `GOOGLE-ADS-FULL-CONTROL-20261013`

Status: **Implementation contract; runtime implementation pending.**

Owner requirement, 2026-10-13 (Asia/Riyadh): المسوّق أو ذكاء ميزان يستطيعان
إنشاء وإدارة حملات جوجل من داخل ميزان، بأوسع تغطية رسمية ممكنة للأنواع،
دون الحاجة إلى فتح واجهة Google Ads للعمل اليومي.

هذه المواصفة لا تثبت وجود تلك القدرات في الإنتاج ولا تغيّر حملة فعلية.
وجود الربط أو إجمالي الصرف لا يغلق المهمة. الأنواع المقيدة لدى جوجل تبقى
فجوة معلنة في هدف «جميع الأنواع»، ولا تُستبدل تلقائيًا بنوع آخر.

## 1. تجربة المستخدم المطلوبة

### المسار اليدوي للمسوّق

داخل مساحة جوجل الحالية في ميزان يستطيع المسوّق المفوّض:

1. اختيار حسابه الإعلاني والهدف ونوع الحملة والمنتجات أو التطبيق المطلوب.
2. إنشاء الهيكل الكامل: الحملة، المجموعات أو مجموعات مواد الإعلان، الإعلانات،
   الكلمات والجمهور والإشارات المناسبة للنوع.
3. ضبط الميزانية بعملة الحساب، المزايدة، الجدولة، المواقع واللغات، الشبكات
   والقنوات المتاحة، والتحويلات المستهدفة.
4. اختيار الصور والشعار والفيديو والمنتجات من مكتبة ميزان، وكتابة النصوص
   وتحريرها ومعاينة متطلبات النوع قبل الإرسال.
5. حفظ مسودة واستعادتها ومشاركتها للمراجعة داخل ميزان، ثم إنشاء الحملة
   عبر الاعتماد والصلاحية المناسبة دون إعادة إدخالها في جوجل.
6. عرض حالة الإنشاء والمراجعة والتسليم والرفض، والتعديل والنسخ والإيقاف
   والاستئناف وإدارة الميزانيات والمزايدات والعناصر من نفس المساحة.

منح دور التسويق وحده لا يعني منح صلاحية إنفاق مفتوحة. تُعرض للمسوّق
حدود تفويضه بوضوح. إعداد الحساب الأولي، الموافقات القانونية، التحقق من
الهوية، الفوترة، وإعادة التوثيق التي تفرضها جوجل تبقى متطلبات خارجية
معلنة عند الحاجة؛ وعد العمل اليومي داخل ميزان لا يخفيها.

### مسار ذكاء ميزان

مثال طلب: «جهّز حملة جوجل لهذا المنتج للسعودية بميزانية يومية ضمن الحد
الذي أحدده». يجب أن يستطيع الذكاء:

- فهم المطلوب واختيار نوع مناسب مسنود ببيانات، أو طلب المدخل المفقود.
- إعداد خطة وهيكل حملة صالحين للنوع، والنصوص والكلمات والاستهداف
  والمزايدة والمواد المطلوبة اعتمادًا على حقائق منتجات ميزان.
- توضيح السبب، مصدر البيانات، الافتراضات، درجة الثقة والمخاطر.
- تقديم مسودة قابلة للتحرير والمعاينة؛ يستطيع المسوّق إكمال مسودة الذكاء
  ويستطيع الذكاء اقتراح تحسين مسودة المسوّق.
- إنشاء الحملة المعتمدة عبر نفس بوابة إجراءات المسوّق، وليس عبر كاتب
  مستقل أو صلاحية مستمدة من نص النموذج.
- متابعة التسليم والأداء ونتائج سلة والتكاليف والربحية المتاحة، واقتراح
  تغييرات قابلة للمراجعة وقياس أثرها وتسجيل نتائجها في ذاكرة العمل.

اقتراح الذكاء للميزانية ليس موافقة على الإنفاق. غياب بيانات تكلفة أو
إسناد موثوق يُعرض كفجوة، ولا يتحول إلى ربح أو ROAS مفترض. تظل الحسابات
المالية وحدود الإنفاق والصلاحيات والتحقق من الهوية حتمية خارج النموذج.

## 2. مصفوفة الأنواع الرسمية

مراجعة وثائق Google Developers بتاريخ 2026-10-13. «متاح رسميًا» أدناه
يعني قابلية API، ولا يعني أن التنفيذ موجود أو مُثبت في ميزان.

| النوع أو المسار | الإنشاء الرسمي | المطلوب داخل ميزان | المتطلبات أو القيود |
| --- | --- | --- | --- |
| Search | متاح | إنشاء وإدارة كاملة؛ RSA والكلمات والمستبعدات والأصول والبحث الديناميكي حيث ينطبق | لا تختزل الهدف في حقل `objective` غير موجود؛ تُركّب المزايدة وأهداف التحويل والإعدادات الصحيحة |
| AI Max for Search | إعداد داخل Search | التحكم في مطابقة البحث وتخصيص النص وتوسيع الرابط بحسب API | ليس نوع حملة مستقلًا؛ تُحترم اعتماديات الإعدادات وقيود الحساب |
| Display | متاح | الإعلانات المتجاوبة والأصول والصيغ المرفوعة المدعومة والاستهداف | التحقق من متطلبات كل صيغة قبل الإنشاء |

| Demand Gen | متاح | صور متعددة، Carousel، فيديو، وإعلانات المنتجات المدعومة | قنوات وجمهور ومتطلبات أصول خاصة؛ فيديو يوتيوب هنا مختلف عن حملة `VIDEO` التقليدية |

| Hotel / Travel | متاح بشروط خاصة | يبقى ظاهرًا في خريطة القدرات كمسار متخصص يحتاج تنفيذه ومتطلباته | Hotel Center/feed وربط الحساب وأهلية العمل؛ لا يُعلن مكتملًا لمجرد دعم PMax العام |
| Video التقليدي (`VIDEO`) | غير متاح لإنشاء حملة جديدة عبر API | استيراد وعرض التقارير؛ بيان قيد الإنشاء والإدارة حسب إصدار API | بعض عمليات الأصول لها استثناءات إصدار؛ لا تثبت إنشاء الحملة. أي مسار إضافي يحتاج إثباتًا واعتماد تصميم مستقلًا |
| Smart الجديدة | لم يعد متاحًا | عرض وإدارة الموجود ضمن ما يسمح به الإصدار؛ بيان منع الإنشاء | Google أوقف إنشاء Smart اعتبارًا من 2026-09-23؛ إنشاء جديد ليس وعدًا قابلًا للتنفيذ |
| Local Services / GLS PMax | الإنشاء غير متاح عبر Google Ads API | عرض الموجود وعمليات التعديل المدعومة مع بيان القيود | لا يُعامل GLS PMax كـPMax عادي؛ أهلية خاصة وعمليات محدودة |
| Call-only القديمة | إنشاء الإعلان الجديد غير متاح | بيان الإيقاف واستخدام RSA مع call assets عند اختياره صراحة | صيغة إعلان قديمة، وليست نوع حملة جديدًا |

كل نوع أو نوع فرعي يعرض أربع حالات منفصلة:

- دعم Google API والإصدار المستخدم.
- تنفيذ ميزان: لم يبدأ / قيد التنفيذ / قابل للاختبار / مثبت.
- أهلية الحساب والمتطلبات الناقصة.
- صلاحيات المستخدم وحدود التنفيذ المعتمدة.

لا يكفي enum أو زر أو نجاح طلب إنشاء الحملة وحده لمنح حالة «مكتمل».
إعادة الاستهداف هدف/استهداف يعتمد على نوع الحملة والبيانات والموافقات،
وليست نوع حملة منفصلًا يُدرج كقدرة مكتملة دون قائمة جمهور صحيحة.

## 4. التنفيذ والاعتماد

كل تغيير من المسوّق أو الذكاء يتبع:

`draft → validate → preview → approve → execute → verify → audit → outcome`

متطلبات البوابة:

- actor مثبت، عزل owner/store/account، دور وصلاحية حديثان، ونوع إجراء محدد.
- سقف ميزانية وتغيّر مسموح وضوابط خسارة/تهدئة وإيقاف طارئ وفق تفويض المالك.
- تثبيت نسخة المسودة والمواد والإعدادات التي تم اعتمادها؛ أي تعديل يلغي اعتماد النسخة السابقة.
- استدعاء `validate_only` حين تدعمه العملية قبل إرسال mutation فعلي؛ نجاحه لا يضمن قبول المراجعة أو التسليم.
- بناء موارد مترابطة في طلب ذرّي حيث يلزم، وعدم ترك حملة بلا مجموعاتها أو أصولها المطلوبة.
- منع التكرار بقيد دائم ومطالبة ذرّية قبل الإرسال. لا يُفترض أن Google يوفر مفتاح idempotency عالميًا للإنشاء.
- حفظ نتيجة الإرسال وهوية الموارد ثم قراءة مستقلة للتحقق. إذا نجح الإرسال
  وفشل التحقق: `outcome_unknown` أو `verification_pending`، بلا إعادة إنشاء عمياء.
- مصالحة الحالات غير المؤكدة بالقراءة، وتتبع الإخفاق الجزئي للموارد والأصول.
- إنشاء حملة paused أولًا عندما تسمح متطلبات النوع، ثم تفعيل منفصل بعد تحقق
  الهيكل وتفويض الإنفاق؛ لا اعتبار «حملة paused فارغة» إنجازًا لمسار الإنشاء.
- الرجوع لإعدادات ما قبل التغيير عندما يكون ممكنًا؛ الإنفاق الماضي لا يمكن
  التراجع عنه، وحذف الموارد ليس rollback عامًا مكافئًا لكل نوع.
- سجل قرارات ومواد واعتماد وتنفيذ ومراجعة ونتائج، من دون أسرار أو بيانات عملاء.

## 5. معيار قبول «تكامل قوي»

لا تُغلق المهمة إلا عند وجود دليل جديد لكل معيار:

1. المسوّق المفوّض يُنشئ من داخل ميزان حملة كاملة لكل نوع مطلوب ومتاح
   رسميًا؛ يرى النوع المقيد أو غير المؤهل وسبب القيد بدل زر نجاح مضلل.
2. حملة أنشأها المسوّق تُعرض في ميزان بأسماء ومعرّفات جوجل الأصلية، مع
   المجموعات/مجموعات المواد والإعلانات والحالة والميزانية والأداء.
3. طلب طبيعي إلى الذكاء ينتج مسودة صالحة قابلة للتعديل والمعاينة، واعتمادها
   ينفّذ عبر نفس عقد المسار اليدوي؛ المسوّق يستطيع تحريرها والعكس.
4. عمليات الميزانية والمزايدة والاستهداف والمحتوى والإيقاف والاستئناف
   المدعومة لكل نوع تعمل مع تحقق ما بعد الكتابة وسجل واضح.
5. Shopping/PMax retail/Demand Gen feed تستخدم المنتجات المطلوبة فعليًا
   من Merchant Center؛ المواد المفقودة أو المنتجات المرفوضة ظاهرة وقابلة للمعالجة.
6. الإعلانات المرفوضة والمراجعة والفوترة ومشكلات التوثيق تُظهر أسبابًا
   عملية صحيحة داخل ميزان، دون الادعاء أن نجاح API يعني أن الحملة بدأت تخدم.
7. إعادة الطلب أو انقطاع الاتصال أو تعارض موظفين لا ينشئ حملة أو ميزانية
   أو إعلانًا مرتين؛ الحالات غير المؤكدة تُصالح دون blind retry.
8. مستخدم متجر آخر أو دور مسحوب أو تفويض منتهي لا يقرأ أو يعدّل بيانات
   الحساب؛ النموذج لا يستطيع منح نفسه صلاحية أو تغيير حدود المالك.
9. التقارير تستخدم عملة الحساب وتوقيته وإسناده الصحيحين. توصيل النتائج
   بسلة والمنتج والتكلفة يدعم قرارات الربحية فقط عند وجود دليل كافٍ.
10. المواد والصيغ والاستهداف والحقول المحددة متوافقة مع إصدار API الحالي؛
    نشر API جديد لا يفتح نوعًا أو صيغة تلقائيًا قبل اختبارات التوافق.
11. الاختبارات تغطي مسارًا كاملًا لكل نوع، الرفض، stale approval،
    scope/tenant isolation، المنافسة، timeout after write والمصالحة.
12. الإثبات الحي المعتمد والمنشور منفصل عن اختبارات provider transport
    المعزولة. تُسجل هوية الإصدار واختبارات الواجهة والتحقق من جوجل؛ نجاح
    fixtures أو CI وحده لا يغلق دليل التشغيل الحقيقي.

## 6. ترتيب التنفيذ

1. تثبيت عقود القراءة والهويات والقدرات حسب النوع والحساب، مع البيانات
   الخاصة بالحملات والمجموعات/الأصول والإعلانات والأداء.
2. بوابة الإجراءات والمسودات والتفويض ومواد الإعلان ومعاينة ثابتة.
3. شرائح رأسية لكل نوع: النموذج → التحقق → هيكل الموارد → الاعتماد →
   provider write → read-back → المصالحة والسجل → واجهة المسوّق.
4. أدوات إنشاء الذكاء فوق نفس عقود المسوّق، ثم تحليلات ومقترحات إدارة
   تعتمد على نتائج سلة والربحية المتاحة.
5. اختبارات تكامل وواجهة ومراجعة، ثم اختبار حي محدود مأذون لكل نوع
   مؤهل، وبعده النشر والتحقق وفق Release Guard v5.

المراحل لا تغيّر النطاق النهائي إلى نوع واحد. وجود شريحة رأسية أولى
يوصف كمرحلة تنفيذ فقط؛ بقية الأنواع ومسار الذكاء تبقى مطلوبة.
