# مخزون ميزان 2 — تسليم فرع التطوير للمراجعة

21 نوفمبر 2026، الرياض. الحالة: **منفذ ومختبر محليًا، متاح للمراجعة؛ لم يُدمج أو يُنشر**.

المستودع `AMASI-SA/AMASI-SA`، الفرع `codex/inventory-ui-replacement-20261120`، مرجع الكود المختبر `55bb3bbfba3d327b5fbe946cfaa85764e136b282`، أساس العمل `734b977de28254c2c089148b4db8972a03ba19eb`. يحتوي التسليم اللاحق على التوثيق والأدلة فقط؛ يسجل القسم المخصص في [سجل المتابعة #1006](https://github.com/AMASI-SA/AMASI-SA/issues/1006#issuecomment-6238987123) SHA التسليم الكامل.

## المعاينة وحدودها

المعاينة المحلية على `http://127.0.0.1:4174/inventory-v2` تشغّل **تطبيق ميزان الفعلي بعد بناء مصدره**، مع مصادقة وبيانات اختبار معزولة وشريط توضيحي. لم ننشئ تطبيق مخزون بديلًا ولا رصيدًا يُخزَّن في المتصفح.

رُصد تقدم فرع الإنتاج على GitHub إلى `c4a83ac18b24f0367b3fbe8052a026c2dbdbac98` أثناء العمل. تغيّر 20 مسارًا في البنوك والأدلة المالية والإصدار، دون تداخل ملفات مع تعديلات المخزون. جرت مراجعة الفروق قراءةً فقط؛ لم ندمج الفرعين. الاختبارات أدناه على مصدر المخزون المذكور، والتكامل مع الرأس الأحدث يحتاج إعادة تحقق قبل أي دمج مصرح به.

في المعاينة فقط: الكتالوج والمكونات وشجرة المستودعات وصفحة الاستلام تستخدم استجابات عرض تجريبية. المشتريات والجرد والتسويات والإدخال المستقل ومسودات إنشاء المنتجات تستدعي خدمات ميزان الأصلية داخل قاعدة Mongo محلية مؤقتة مستقلة. اختبارات الواجهات الأخرى تستخدم استجابات API محددة لاختبار النماذج والصلاحيات والأخطاء؛ لا تثبت حفظ كل تعديل عرض تجريبي على قاعدة مشتركة. أدوات الاختبار خارج `frontend/src` وليست مزودات بيانات إنتاجية.

لا تتصل المعاينة بـ mezansalla.com أو قاعدة الإنتاج، ويحجب خادم الاختبار نشر المنتجات إلى سلة. لم يُجرَ تحقق بصري من الموقع الحالي؛ الواجهات مبنية على الكود والمرجع المعتمد ولقطات المشروع.

## الشاشات المنفذة

| الشاشة | السلوك المنفذ والعقد المستخدم |

| الأصناف | بحث وصورة وSKU وحالات وكميات وتفاصيل جانبية؛ كتالوج المنتجات وتكاليفه وخياراته على خدمات `products-v2` الحالية. |
| المكونات | إنشاء وتعديل المكونات والخدمات وتصنيفاتها وربطها بالمنتجات، والتمييز بين التكلفة المرجعية والمعتمدة. |
| البكجات | محرر التركيب الحالي داخل التصميم الجديد، وحفظ سياسة التكلفة والربط بالمكونات وفحوص الدورات والحدود القائمة. |
| إضافة المخزون | بحث بالصورة والرقم المخزني، خيارات وحالة تخصيص وكمية وتكلفة وموقع وإجمالي؛ معاينة الخادم ثم حفظ ثابت الهوية واستعادة الطلب المعلّق. الإدخال المستقل يظل بانتظار التقييم. |

| الاستلام | مراجعة الفواتير وحالة البنود، اختيار الخانة والتحقق من باركودها، ومطابقة حالة التجهيز والمواصفات للمسودة قبل الاعتماد. صلاحية السداد مستقلة. |
| المستودعات | فرع وقسم ودولاب ورف وخانة؛ خريطة وقائمة وبحث وإشغال وطباعة باركود. تسميات عرض مختصرة مثل `د1 / ر2 / خ3`، والهويات والباركودات الفعلية محفوظة. |
| الجرد | اختيار مستودع أو خانات محددة، مسودة قابلة للاستكمال، كمية مسجلة وفعلية وفرق وتكلفة وسبب لكل فرق. الفراغ يعني «لم يُجرد»، والصفر كمية فعلية صفر. |
| التسويات | إرسال ومراجعة واعتماد ورفض وإعادة للتعديل، ثم تأكيد منفصل للترحيل بصلاحية صريحة. كميات وتكلفة وقيود وإيصالات وحالة نهائية في معاملة أصلية واحدة. |
| حركة المخزون | قراءة الاستلام والصرف والتسويات المثبتة، بحث وتصفية بالتاريخ والصنف والمستودع وتفاصيل المصدر؛ لا تُحسب الأرصدة من سجل متصفح. |
| التقارير | تجميع الأرصدة والقيم حسب المستودع والوحدة، وفصل المحجوز والمتاح والموقوف؛ القيمة غير المعروفة لا تتحول إلى صفر. |

التنقل والنماذج متجاوبة على الكمبيوتر والجوال. تشمل الحالات التحميل والحفظ والنجاح والبيانات الفارغة والمدخلات غير الصالحة وتعذر الخدمة وسحب الصلاحية وتعارض الإصدار وفقدان رد الحفظ. تبقى المدخلات عند الخطأ، وتُمنع إعادة الإرسال المتزامنة وإغلاق النماذج أثناء الحفظ.

## دورة الجرد وحماية القواعد القائمة

- الرصيد الوحيد هو `warehouse_locations`، والتكلفة هي المتوسط المرجح الحالي `mz2_inventory_cost_states`. مستندات الجرد تحفظ المقارنة والقرار والتدقيق فقط.
- الترحيل يستخدم سياج الإدخال ومعاملة المالك وكاتب القيود V2 المختوم الموجود. لا يستخدم إدخال الافتتاحية لتسوية الفروق.
- تُراجع الصلاحيات وحسابات الربط والفترة المحاسبية والأرصدة والتكاليف والحجوزات وسعة الخانة داخل المعاملة. المقارنة التي تغير أصلها تحتاج تحديثًا ومراجعة جديدة.
- معرّف الترحيل يصدره الخادم للإصدار المعتمد. إعادة الطلب بعد فقدان الرد تستعيد نتيجته دون مضاعفة الكمية أو القيد. اختُبرت عمليتا ترحيل متزامنتان وعمليتا جرد تتنافسان على الرصيد نفسه والتراجع الكامل عند فشل بعد إنشاء القيد.
- يحفظ التدقيق اسم الموظف وهويته والوقت والإصدار والسبب والقيم قبل التعديل وبعده ومقارنة البداية والبنود المقدمة والمعتمدة والمرحّلة ومرجع القيد. حد الحجم يوقف الإجراء بدل حذف التاريخ.
- الزيادة تنشئ إيصال تسوية أصليًا دون اختلاق دليل تصنيع أو استهلاك مكونات، والنقص لا يتجاوز المتاح بعد الحجز. الوحدات الأصلية محفوظة دون تحويلات مفترضة.
- الحفظ والإرسال والاعتماد لا يفعّلون ترحيل الإنتاج. مسار الترحيل مغلق افتراضيًا ويحتاج التفعيل البيئي والضوابط الحالية وصلاحية `accounting.inventory.adjustments.post` الصريحة. تحتاج المراجعة أيضًا صلاحية صريحة، بما فيها المالك.

تفاصيل API والصلاحيات في [STOCKTAKE-CONTRACT.md](STOCKTAKE-CONTRACT.md).

بلا أخطاء JavaScript أو تمدد أفقي للصفحة في مجموعتي المتصفح. اختُبرت زيادة ونقص ومكونات بكسور ووحدات مختلفة وجرد جزئي وتعارض وتزامن وحجوزات وسحب صلاحية وحدود السعة وفشل المعاملة وإعادة الطلب بعد فقدان الرد. الأدلة وأسماء الاختبارات ومرجع المصدر في [evidence/verification.json](evidence/verification.json)، واللقطات الفعلية المختارة في [evidence/screens](evidence/screens).

تحذيرات بناء قائمة: ترتيب استيراد CSS وحجم بعض الحزم واستيراد ثابت وديناميكي للملفات نفسها، وتحذير إعداد Vite لتحميل CommonJS. لا ندّعي إصلاح بناء الإصدارات أو جميع فحوص المستودع. لا توجد PR أو CI لهذا الفرع؛ الأدلة المذكورة محلية.

## حدود معلنة وما يحتاج تحققًا لاحقًا

1. المعاينة ببيانات اختبار فقط. إثباتها على بيانات التاجر في بيئة اختبار ومراجعة الصلاحيات وربط الحسابات يسبقان أي إطلاق مصرح به. لم ننقل بيانات أو نُصلح تعريفات منتجات الإنتاج.
2. الخيارات من التعريف والنسخة المخزنية الحاليين فقط. التعريف الناقص أو التركيبة غير الموثوقة يظهر كخطأ؛ لا تُخترع ألوان أو مقاسات أو تكلفة. رفع ملف تخصيص غير مدعوم في عقد إدخال المخزون الحالي ويحتاج تطويرًا مستقلًا.
3. دورة فواتير G47 الحالية تستلم جميع البنود معًا؛ لم نضف استلام فاتورة جزئيًا أو قواعد محاسبية أخرى. الفواتير القديمة تبقى للعرض بحسب العقد القائم.
4. الحركات أحدث 500 حدث مثبت مع تنبيه عند عدم الاكتمال، والجرد أحدث 200 مستند. التصفية على النافذة المقروءة. الجرد الواحد حتى 500 بند ويمكن تحديد خانات أصغر. التصفح الخادمي لكل التاريخ والأرشفة يحتاجان توسعة مستقلة؛ لا تمثل النافذة سجلًا كاملًا عند ظهور التنبيه.
5. تحفظ `purchase_configuration` نص التخصيص الأصلي، وتبقى مواصفات المطابقة المخزنية مطبّعة بالقواعد الحالية، بما فيها حالة الأحرف. لم نغيّر هوية الرصيد أو قواعد المطابقة لتحسين العرض.
6. التفعيل الإنتاجي والنشر وإثبات بروتوكول Release Guard v5 على Emergent غير منفذة. لم تُنشأ lease ولم يتغير intent أو كميات أو قيم أو صلاحيات الإنتاج. يلزم إذن مستقل قبل الدمج أو النشر أو التفعيل.

الخطوة التالية الآمنة هي مراجعة المعاينة والفرق على فرع التطوير. إعادة الاختبارات موثقة في [README الاختبار](../../../scripts/testing/inventory_suite/README.md). تعديلات Qoyod والطلبات غير المتعلقة بالمهمة في مساحة العمل الأصلية محفوظة دون مساس.
