# Native stocktake contract (development)

The only quantity authority is `warehouse_locations`. Counts and audit history are documents, not a second stock balance. Costs remain native moving weighted average; counts never alter the opening-stock writer. Posting is closed unless `MEZAN_STOCKTAKE_POSTING_ENABLED=1`, the existing physical inventory control and accounting controls are open, the approved opening is verified and the actor has an explicit posting grant. This task does not enable any of those in production.

Base: `/inventory-v2/stocktakes` (existing authenticated `/api` client).

- `GET /context`: `schema_version: g47-stocktake-v1`, `capabilities: {view,count,review,post}`, `posting_enabled`, `posting_blockers: [{code,message}]`, `warehouses: [{id,name}]`, `inventory_accounts: [{entity_id,label}]`, `variance_accounts: [{code,name}]`. Variance accounts are existing active expense categories selected explicitly; no account is generated.
- `GET /`: `{items:[count summaries],read_only:true,schema_version}`. Summary: id/title/status/revision/created_at/created_by/updated_at/warehouse_ids/counted_lines/variance_lines/increase_value/decrease_value. No client sums across units.
- `GET /:id`: complete saved document including `lines`, `audit`, `capabilities`, `posting_enabled`, `posting_blockers`. Each line: id/name/sku/kind/unit/location_id/location_code/warehouse_id/warehouse_name/preparation_state/specifications, `recorded_quantity`, `counted_quantity` (nullable string), `difference` (nullable string), `unit_cost` (nullable string), `difference_value` (nullable string), `reason`. Never render unknown as zero.
- `POST /`: `{request_id,title,warehouse_ids:[],location_ids:[],row_ids:[]}` creates a real snapshot draft; explicit filters optional, max 500 rows. Empty scope is an error. Response full document. Replaying the exact request recovers it.
- `PUT /:id`: `{request_id,expected_revision,title,lines:[{id,counted_quantity:null|string,unit,reason}]}` saves/resumes draft/returned. Omitted lines stay unchanged. Blank means uncounted; partial counts never zero other rows. Counts use the stored native unit; product quantities integral, component quantities up to 6 decimals. No guessed unit conversion.
- `POST /:id/actions`: `{request_id,expected_revision,action:submit|approve|reject|return|refresh_snapshot,reason,inventory_account_id?,variance_account_code?}`. Submit sends counted differences for review, requiring reasons and explicit account mappings. Approve/reject/return require fresh review grant; refresh_snapshot is explicit in editable states, retains counts for identical rows, invalidates prior comparison. All actions CAS on revision and audit the real actor. Replayed exact commands recover; conflicting replay keys fail.
- `POST /:id/post`: `{operation_id,expected_revision}`. `operation_id` is server-issued `posting_operation_id` of the approved revision. Fresh actor, grants, quantities, costs, reservations, location capacity, accounting readiness and periods are rechecked inside the existing owner transaction/admission. Returns the posted full count. Retry the same operation after a lost response; no new key. No automatic posting from approve or save.

States: `draft → submitted → approved → posted`; `submitted|approved → rejected|returned`, `returned → submitted`; no quantity write in drafts/review. Display errors inline without discarding input. On revision/snapshot conflict ask the user to reload or explicitly update comparison; never force overwrite. Context failure/revoked permission clears saved views and actions. Readonly employees never fetch this writer workspace.

Registry actions: `accounting.inventory.count`, `accounting.inventory.adjustments.review`, `accounting.inventory.adjustments.post`. Review and posting require explicit grants including owners. Existing warehouse assignment remains authoritative. Metadata edits are atomic single-document CAS; physical effects, sealed V2 journal, source receipts and final count state commit in one native transaction. Positive differences create native adjustment receipts without claiming manufacturing/component provenance. Negative differences cannot consume reservations or held/ambiguous lots.
