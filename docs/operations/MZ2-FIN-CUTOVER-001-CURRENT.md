## مسار الاستكمال دون تدخل مالي

1. أكمل بوابة تنفيذ P01 وادمج فقط بعد مراجعة وسياسة المستودع.
2. ابنِ P02 إلى P08 بالتتابع وفق dependencies، مع الاختبارات، دون Publish
   أو كتابة Production مالية. استخدم `QUEUED` قبل بدء كل مرحلة و
   `IN_PROGRESS` بعد بدء عملها؛ لا تدّعِ أنها منفذة مسبقًا.
3. يجب أن يتضمن المصدر حاجز Backend مركزيًا يمنع جميع كتابات القيود
   العادية قبل `safe_active`، ومسارًا افتتاحيًا وحيدًا محكومًا.
4. بعد اكتمال جميع بوابات التنفيذ، ثبّت source commit A وأنشئ intent commit
   B فقط وفق Release Guard v5.
5. توقف عند مرشح إصدار متحقق محليًا ينتظر موافقة Publish.
6. بعد موافقة Publish المنفصلة، انشر الحزمة مرة واحدة وهي خاملة ماليًا،
   ثم نفذ Release Guard verify واختبارات Production غير المالية.
7. اجمع أدلة الأقسام الثمانية وأنشئ المعاينة. لا ترحلها دون تفويض مالي
   صريح مستقل.
8. بعد ترحيل القيد الافتتاحي والتحقق منه، يجب أن يصبح
   `safe_active=true` قبل السيناريو 6 وقبول P08.

## عقد الحالة

نجاح الكود أو CI أو الدمج لا يجعل المرحلة `COMPLETE`. تستخدم
`RUNTIME_ACCEPTANCE_PENDING` حتى نشر Runtime وقبوله. لا تصبح المرحلة
المالية `COMPLETE` قبل قبولها بعد `safe_active=true`.
