# G47 — تهيئة المخزون الافتتاحي المعتمدة

هذا مسار API معزول للاستيراد والمراجعة والاعتماد، ولا يعمل تلقائيًا عند التشغيل أو النشر. لا ينشئ قيدًا ماليًا جديدًا؛ يقارن الأدلة بالقيد الافتتاحي المعتمد والمختوم في Ledger V2، ثم يهيئ الكمية والتكلفة داخل معاملة Mongo واحدة. لم يُنفّذ هذا المسار على Preview أو Production ضمن تطوير G47.

## العقد

- الكمية الحالية مصدرها الوحيد `warehouse_locations.occupancy.items`.
- متوسط التكلفة المعتمد مصدره `mz2_inventory_cost_states`، بالسياسة `moving-weighted-average-v1`.
- `opening_quantity` و`opening_total_cost` في سجل التكلفة أدلة افتتاحية ثابتة، وليستا رصيد كمية حاليًا.
- يجب أن يكون الفاعل مالكًا بصلاحية `accounting.opening_balances.approve`. يُعاد التحقق من المستخدم داخل المعاملة، وتبقى حواجز توقف الكتابة والفترة المحاسبية فعالة.
- يجب وجود opening فعّال متحقق منه و`safe_active`، وأن يتطابق مرجع الدليل وتوقيت القطع ومعرّف القيد مع إعداد القطع الحالي. يستخدم المسار واجهة القراءة العامة للقيد المختوم؛ لا يغير الكاتب المحاسبي.
- يجب أن يطابق مجموع التقييم لكل `inventory_account_id` رصيد Inventory Asset في القيد الافتتاحي الفعّال، دون تسوية بالاسم أو تجاهل حساب آخر.

## ملف الدليل

يرسل المالك ملف JSON أصليًا إلى `POST /api/opening-inventory/imports` بالحقل multipart المسمى `file`. تحفظ بايتات الملف كما هي في مستودع الأدلة الداخلي مع SHA-256. الحد الأقصى 10 MiB. الأرقام سلاسل عشرية صريحة؛ لا صيغ Excel ولا تكلفة مشتقة من آخر شراء.

مثال اصطناعي؛ يجب أن يكون رصيد المخزون الافتتاحي المقابل 20.00 وأن تكون الهويات والموقع مسجلة بالفعل:

```json
{
  "schema_version": "g47-opening-inventory-v1",
  "cost_policy_version": "moving-weighted-average-v1",
  "cutover_at": "2026-09-01T00:00:00+03:00",
  "opening_txn_group_id": "SYNTHETIC_APPROVED_OPENING_ID",
  "evidence_ref": "SYNTHETIC_APPROVED_INVENTORY_SHEET",
  "rows": [
    {
      "item_type": "STOCK_COMPONENT",
      "resource_id": "synthetic-component",
      "category_id": "synthetic-category",
      "inventory_account_id": "synthetic-inventory-account",
      "opening_quantity": "4",
      "opening_unit_cost": "5.000000",
      "opening_total_cost": "20.00",
      "allocations": [
        {
          "location_id": "synthetic-location",
          "quantity": "4",
          "scanned_location_barcode": "SYNTHETIC-LOCATION",
          "preparation_state": "requires_preparation",
          "specifications": {}
        }
      ]
    }
  ]
}
```

للمنتج يستخدم الصف `item_type: PRODUCT` مع `product_id` و`variant_id` إذا كان للمنتج متغيرات، دون `resource_id`. لكل متغير صف مستقل. المنتج الذي لا يملك متغيرات لا يحتاج `variant_id`. لا تقبل الخدمات أو موردًا غير نشط أو غير متتبع مخزنيًا. لا يكفي SKU وحده لإثبات الهوية.

الكمية والتكلفة موجبتان وبدقة لا تتجاوز ست منازل عشرية؛ كمية المنتج عدد صحيح. المبلغ الإجمالي بدقة هللتين ويطابق الكمية × التكلفة بالتقريب المالي. توزع هللات التقييم على المواقع توزيعًا حتميًا يحافظ على الإجمالي. يجب أن يساوي مجموع كميات المواقع كمية الهوية. الموقع دائم ومتاح، وباركوده وسعته مطابقان؛ لا خلط هويات في موقع واحد.

## المراجعة والاعتماد

الاستيراد يحفظ مسودة فقط. الاستجابة و`GET /api/opening-inventory/imports/{id}` تعرضان:

- الوثيقة والخطة والهويات والتوزيع والتقييم؛
- `evidence_sha256` و`source_file_id`؛
- `baseline_locations` و`baseline_sha256` للمخزون السابق؛
- حالة الاستيراد ومن أنشأه.

بعد مراجعة البيانات، يرسل المالك إلى `POST /api/opening-inventory/imports/{id}/approve`:

```json
{
  "approve": true,
  "evidence_sha256": "<SHA-256 returned by import>",
  "baseline_sha256": "<SHA-256 returned by import>"
}
```

هذه قوالب طلبات وليست أوامر للتنفيذ التلقائي. يتطلب أي تنفيذ فعلي التفويض التشغيلي المستقل المناسب.

يعيد الاعتماد فحص أصل الدليل وبصمته، والافتتاح، والمخزون، والكتالوج، والحراس داخل المعاملة. عند النجاح يكتب إيصالات افتتاحية ثابتة وسجلات التكلفة والكميات وسجل اعتماد واحدًا للمالك. لا يكتب قيد افتتاح آخر أو Legacy Ledger.

## الحالات التي تمنع التنفيذ

- كمية موجبة بلا تكلفة صريحة موجبة، أو متغير مفقود، أو تقييم لا يطابق القيد؛
- إغفال أي موقع ذي مخزون موجب، أو اختلاف الكمية القديمة عن الدليل في موقع موجود؛
- اختلاف تهيئة الصنف أو مواصفاته أو حالته التحضيرية؛ لا يحول الاستيراد المخزون إلى جاهز بإسقاط هذه البيانات؛
- تغير المخزون أو الكتالوج أو القيد أو الملف بعد المراجعة؛
- وجود كلفة مخزون معتمدة سابقة، أو إيصال G47، أو أي خطة/وحدة/مسار قبول للمكونات؛ حتى دون قيد مالي؛
- أي نشاط محاسبي تشغيلي بعد الافتتاح، أو تجاوز نطاق القراءة الآمن للقيد؛
- فترة مقفلة أو توقف الكتابة أو فقدان صلاحية المالك.

عند اعتماد مخزون موجود ومتطابق، تحفظ معرفات دفعاته وإيصالاته ومصدره ومواصفاته ودليل منشئه، مع توحيد الهوية فقط. وجود دليل تصنيع أو استهلاك مكونات قديم في الصنف أو إيصال مصدره يمنع الاستيراد برسالة مصالحة صريحة؛ لا يحذف هذا الدليل ولا يعاد احتساب استهلاك تاريخي. الإيصالات الجديدة من `opening_inventory` لا تمنح إعفاء تصنيع؛ يظل الطلب اللاحق خاضعًا لحجز وصفته الفعلية.

إذا كان الافتتاح يحتوي رصيد مخزون موجبًا، فإن شراء G47 أو سداد المورد يشترط علامة التهيئة المعتمدة المرتبطة بنفس القيد الافتتاحي الفعّال. هذا يمنع إنشاء أول قيد تشغيلي قبل إتمام التهيئة ثم إغلاق مسارها. الافتتاح ذو رصيد المخزون الصفري لا يتطلب استيراد مخزون وهمي.

## القراءة اللاحقة وإعادة المحاولة والتراجع

بعد الاعتماد، تقرأ الحالة من نفس `GET`، وتطابق `receipt_ids` والهويات والكميات والتقييم ودليل الاعتماد. يجب أن يبقى القيد الافتتاحي نفسه وبصمته دون تغيير. الشراء التالي يستخدم كمية المواقع الحالية ومتوسط التكلفة الافتتاحي المعتمد لحساب المتوسط المتحرك.

إعادة رفع البايتات نفسها تعيد الاستيراد نفسه. إعادة اعتماد معرف الاستيراد والبصمتين نفسهما تعيد النتيجة المعتمدة دون مضاعفة الكمية. لا تقبل تهيئة ثانية للمالك من ملف مختلف؛ ليست هذه أداة backfill أو تصحيح تاريخي.

فشل المعاملة قبل إتمام الاعتماد يتراجع عن كل آثار المخزون والتكلفة والإيصالات؛ يمكن إصلاح المانع وإعادة الطلب نفسه إذا بقيت بصمات المراجعة مطابقة. قبل الاعتماد يمكن ترك المسودة دون تنفيذ. بعد نجاح الاعتماد لا يوجد حذف أو استعادة تلقائية؛ أي تراجع يحتاج مراجعة وتفويضًا مستقلين وخطة مصالحة تراعي العمليات اللاحقة. لا تُحذف قيود أو إيصالات منشورة لإعادة المحاولة. إزالة الشيفرة وحدها لا تعكس حالة سبق اعتمادها.
