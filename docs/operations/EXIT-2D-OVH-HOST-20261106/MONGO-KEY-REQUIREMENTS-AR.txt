متطلبات نقل مستقبلي — أسماء وشروط فقط، لا بيانات ولا قيم أسرار

لم يُتصل بقاعدة الإنتاج أو إعداداتها أو بيئتها، ولم تُجمع بصمات مفاتيح فعلية.
هذه القائمة مستخرجة من المصدر البرمجي وتكمل CUTOVER-AND-RESTORE.txt السابق.

قائمة MongoDB التي يجب اعتمادها لاحقًا من مشغّل مخوّل:
- الإصدار/FCV، topology وreplica set، TLS/CA، المصادقة والأدوار؛ التوافق
  بين أدوات dump/restore والخادم. قاعدة الاختبار الحالية لا تثبت توافق قاعدة مجهولة.
- حصر جميع collections/indexes/unique/sparse/partial/TTL/collations/validators،
  counts وحجوم البيانات والفهارس، BSON types وأزمنة UTC، IDs وتسلسلات counters.
- سجلات قيود والفواتير وربط IDs المزود؛ Salla webhook inbox، queue/outbox،
  مفاتيح idempotency، worker leases/fencing، checkpoints، unknown outcomes.
  لا تصفّرها، ولا تعِد إرسال الغامض، ولا تُعدّل TTL لبيانات مالية لتسهيل النقل.
- طريقة النسخ المتسقة: توقف جميع الكتّاب والتحقق من الهدوء، أو snapshot/oplog
  مدعوم كامل واختباره؛ لا تفترض أن dump لقاعدة واحدة مع oplog يضمن الاتساق.
- جرد GridFS/المرفقات/ملفات المورد/PDF/media ومسارات volumes والأذونات والحجم
  وchecksums؛ حصر أي تخزين خارجي/روابط مؤقتة/تنظيف TTL، وحفظ الروابط بين DB والملفات.
- مساحة حقيقية + نمو + مساحة dump/restore/cache/logs/صور Docker واحتياطي؛
  75GB ليست كلها مساحة Mongo. الاختبار السابق على قرص5GB لا يقدّر حجم الإنتاج.
- استعادة في قاعدة فارغة معزولة أولًا؛ تطابق hashes لكل المستندات والفهارس
  ومعرفات أعمال مختارة، فك تشفير عيّنات اصطناعية بمفاتيح الاختبار، ثم دليل
  منفصل لاحقًا لصلاحية مفاتيح الإنتاج عبر قناة آمنة. لا تقارن القيم عبر Issue/CI.

مفاتيح أصلية يجب الحفاظ على هويتها عند النقل لاحقًا، لا توليد بديل عشوائي:
- SALLA_TOKEN_ENC_KEY وSALLA_TOKEN_ENC_KEY_OLD إن وجد:
  backend/salla_integration/crypto.py؛ القديم مسار فك تشفير احتياطي.
- QOYOD_TOKEN_ENC_KEY وQOYOD_TOKEN_ENC_KEY_OLD إن وجد:
  backend/integrations/qoyod/crypto.py؛ التوكنات المخزنة تعتمد عليهما.
- MFA_ENCRYPTION_KEY إن كانت مضبوطة؛ وإلا راجع fallback المشتق من JWT_SECRET
  في backend/mfa_security.py. فرض مفتاح جديد قد يُعطّل MFA السابق.
- JWT_SECRET: الجلسات/HMAC/OTP ومسار MFA القديم؛ خطط قرار استمرار الجلسات
  أو إنهائها بشكل معتمد. لا تدوير أو استبدال ضمن هذه التجربة.
- بيانات مزوّدي سلة وقيود والإعلانات والشحن/SMTP/Webhook signing secrets:
  حصر الأسماء/الاستخدام/المالك/نسخة السر فقط في المرحلة القادمة، دون تفعيلها
  في التجربة الاصطناعية. الحارس الحالي يرفض مفاتيح المزوّدين عمدًا.

البيانات الوصفية المطلوبة فقط عند التفويض: وجود السر، المالك، مرجع خزنة آمن،
النسخة/التاريخ، وخطة تحقق fingerprint داخل جلسة خاصة. لا توضع قيم أو
fingerprints حالية في Git أو PR أو Issue أو سجلات الاختبار.
احتفظ بنسخة escrow منفصلة للمفاتيح الأصلية عن النسخة المشفّرة للبيانات.
مفتاح restic خاص بالنسخ وليس بديلًا عن مفاتيح تطبيق ميزان. فقد أي منهما
قد يمنع الاستعادة، لذا يلزم اختبار استرجاع كل فئة وفق التفويض لاحقًا.
