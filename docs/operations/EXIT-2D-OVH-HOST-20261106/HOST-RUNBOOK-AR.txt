جاهزية تجربة VPS-2 واحد — ملفات مراجعة؛ لم تُنشأ موارد ولم تُطبّق أوامر على OVH

الحالة المالية والاختيار
المطلوب Standard VPS-2 بألمانيا: 4vCPU/8GB/75GB NVMe. تحقّق من SKU الفعلي
والدولة المتاحة؛ لا تستبدله بـLocal Zone ولا تشترِ تلقائيًا SKU أحدث مختلفًا.
Hobby Render وأي ثلاثة VPS ليست ضمن التنفيذ المختار.
8.50USD سعر ابتدائي عام سابق وليس عرض فوترة السعودية. لا يوجد سعر نهائي
أو ضمان مخزون Frankfurt من دون سلة الحساب. رسوم الإعداد/الضريبة/الالتزام
والتجديد وخيار الترقية يجب تثبيتها في السلة قبل الشراء. لا تفترض ترقية SKU
أمريكي خارج الولايات المتحدة؛ اطلب تأكيد أهلية SKU الألماني المحدد للترقية.

إن عرض مواصفات أخرى، ابدأ من https://www.ovhcloud.com/en/vps/ واختر يدويًا
المواصفات المطلوبة. اختر حسابًا وبلد فوترة Saudi Arabia مطابقين لبيانات
الدفع والمؤسسة، ثم Germany/Frankfurt أو وصف مركز البيانات الفعلي المعروض،
Linux بلا رخص مدفوعة، وأقل مدة التزام مناسبة. قارن الشهرية والسنوية دون
إتمام الدفع. انسخ ملخص السلة فقط: SKU/المركز/العملة/المبلغ الأول/الضريبة/
الإعداد/النسخ الاحتياطي المشمول والإضافي/التجديد/الالتزام/الإلغاء. لا بيانات بطاقة.

الإضافات الاقتصادية المقترحة، تقديرية وليست موافقة مالية:
- Caddy + nftables + systemd + مراقبة Python محلية + restic: لا رسوم ترخيص.
- نسخ خارجي R2 Standard: قد يبقى صفرًا ضمن حصة الحساب المجانية 10GB-month
  وطلبات الفئة A/B المجانية. حد الأداة8GB احتياط تشغيلي وليس سقف فاتورة من المزود،
  والحصة مشتركة على الحساب. خارجها0.015USD/GB-month والطلبات حسب التسعير.
  لا يُنشأ bucket أو حساب الآن؛ راجع أي طلب تفعيل فوترة منفصلًا قبل الموافقة.
- مراقبة توافر خارجية مجانية ممكنة لاحقًا؛ لا حساب أو إشعارات أو Webhook مفعّل.
  المراقبة المحلية تحفظ التنبيهات في journal وJSON؛ يلزم تعيين مستلم/قناة لاحقًا.
- الإدارة الذاتية بلا رسم مزود إضافي، لكنها تتطلب وقت تحديث أمني واستعادة
  ومتابعة؛ لا توجد خدمة إدارة مدفوعة أو وعد بصفر تكلفة وقت الموظفين.
المجموع = سلة VPS السعودية + أي إضافات معتمدة + ضريبتها. مثال حسابي فقط:
8.50 ×1.15 =9.775≈9.78USD إذا كان الأساس8.50 ومعدل الضريبة15% فعلًا؛ ليس عرضًا.
لا تُحذف البيئة باعتبار انتهاء الاختبار إلغاءً للعقد: أوقف التجديد/ألغِ الخدمة
وكل إضافة من لوحة المزود وفق شروط السلة، وبعد تصدير الأدلة والنسخة الاصطناعية
إن لزمت. حذف Docker وحده لا يوقف فوترة VPS. لا ينفَّذ حذف أو إلغاء الآن.

الحدود والموارد
خمس خدمات دائمة كما في Compose المعتمد، ومهمة migration قبل التطبيقات.
3.5CPU/5888MiB لمجموع الخدمات، ويبقى هامش للـOS وTLS والمراقبة. الخدمات
تتشارك kernel/قرص/شبكة ومصدر عطل واحد؛ فصل العمليات ليس توافرًا عاليًا.
Caddy192MiB/0.2CPU، مراقبة96MiB/0.05CPU متقطعة. Backup768MiB/1CPU
داخل نافذة صيانة تتوقف فيها التطبيقات؛ لا تشغّله أثناء قياس الأداء.
لا يُعدّل منطق المحاسبة ولا الفواتير ولا fencing داخل التطبيق.

التحضير بعد موافقة السعر وإنشاء الخادم بتفويض مستقل
1. Ubuntu24.04 LTS، SSH بمفتاح، console/KVM متاح، حساب إدارة مع sudo، تحديثات
   أمنية. ثبّت Docker Engine/Compose وCaddy وnftables وrestic من مصادرها الرسمية.
   ثبّت الإصدارات/بصمات الصور المستخدمة واحفظها مع أدلة الخادم قبل التجربة.
2. احصل على checkout نظيف للمرشح المعتمد، وافصل source الصورة المثبّتة عن
   أي مرشح تكامل جديد. source_sha في host.json ووسم الصور وbuild-meta يجب أن تتطابق.
   لا تُبدّل قيمة901 لصورة من مصدر مالي أحدث. لا تجمع أسرار الإنتاج.
3. secrets جديدة اصطناعية فقط خارج المستودع: init_secrets.py بدون --ci-fixture،
   root0700/files0400 UID65532. لا تستخدم كلمات مرور CI العامة على الخادم.
   لا تفتح DB للإنترنت. لا تضع مفاتيح سلة/قيود/سناب أو SMTP/Webhooks حقيقية.
4. عدّل host.example.json بالمسارات/اسم مضيف تجربة مخصص/واجهة الشبكة الفعلية
   وعناوين الإدارة فقط. source901 صالح للمرجع القديم؛ لا يعتبر دمج الإنتاج.
   احفظ host.json خارج المستودع. أي DNS لتجربة أو تغيير DNS قائم يحتاج موافقته؛
   لا نستخدم دومين الإنتاج، ولا نطلب شهادة ACME الآن.
5. ولّد ملفات للمراجعة فقط:
   python packaging/exit2d/ovh_host/generate.py --config /private/host.json --output /private/review
   لا يثبّت هذا الأمر خدمات ولا يفعّل مؤقتات أو قواعد جدار ناري.
6. راجع mezan-trial.slice وcompose.env وmezan-stack.service وmezan-tls.service.
   compose.env غير سري ويحمل المسارات/SHA فقط. up --no-build يرفض صورة غير
   موجودة؛ ابنِ الصورة المثبتة قبل التشغيل، ثم شغّل migration وراقب خروجه الناجح.
   لا تفعّل boot units حتى تنجح تجربة reboot المنفصلة على الخادم الاصطناعي.
7. راجع firewall.nft عبر nft -c. لا تستخدم flush ruleset ولا تغيّر سلاسل Docker.
   القواعد تملك inet mezan_trial فقط؛ INPUT يسمح loopback/established/ICMP و80/443
   وSSH من CIDRs الإدارة. FORWARD يحجب الاتصالات الجديدة الواردة من واجهة الإنترنت
   حتى لو نشرت حاوية منفذًا عبر DNAT. لا تغلق جلسة الإدارة؛ console وجلسة SSH ثانية
   وموعد rollback مؤقت وشبكة IPv6 يجب اختبارها قبل تثبيت القواعد بعد موافقة التنفيذ.
8. Caddy على المضيف يمرر إلى127.0.0.1:10000، وReports/Mongo/Workers بلا منافذ عامة.
   admin API مغلق، TLS1.2/1.3، X-Forwarded-Proto=https؛ لا يستخدم HTTP/3/UDP443.
   الاختبارات المعزولة تستخدم CA داخليًا موثوقًا صراحة، بلا تجاوز تحقق TLS؛
   الشهادة العامة الحقيقية وتجديدها وIPv6 وفحص WAN شروط قبول لاحقة وليست مثبتة الآن.

تجهيز البيانات الاصطناعية على الخادم لاحقًا
- بعد migration وفي قاعدة فارغة فقط، جهّز private-fixture directory0700 UID65532.
  اضبط MEZAN_FIXTURE_DIR، ثم استخدم base compose +ovh_host/compose.tools.yaml
  مع --profile tools run --rm --no-deps fixture --ack-synthetic-only --source-sha <reviewed SHA>.
- الأداة تولّد5000طلب وبيانات تجهيز، وكلمة موظف عشوائية في ملف0400 خارج Git.
  ترفض إعادة البذر أو overwrite. لا تغيّر كلمة مالك الحساب أو إعداد MFA له.
  failure جزئي يترك marker غير ready؛ عالجه بإعادة قاعدة التجربة الفارغة عمدًا،
  لا بإزالة marker وإعادة البذر فوق بيانات جزئية. لا تغيّر بيانات غير اصطناعية.
- سجّل دخول المالك الحقيقي للتجربة وأكمل MFA له. SMTP الاختبار capture محلي
  ولا يرسل للإنترنت؛ اقرأ OTP الاصطناعي عبر وصول إداري خاص، ولا تنشر capture.
  هذه أدوات قبول مغلقة، لا بيانات عملاء ولا أشخاص حقيقيين ولا Webhook حقيقي.

القياس الفعلي من الرياض، بعد تفويض التنفيذ فقط
1. سجّل UTC وSKU والمنطقة الفعلية وإصدارkernel/Docker والصور، واتصال العميل
   بمدينة الرياض/مزود الإنترنت/VPN إن وجد. لا تستنتج الموقع من timezone.
2. شغّل monitor.timer دقيقة أثناء التجربة؛ يحفظ CPU وRAM الحالية/الذروة منcgroup
   وOOM/restarts وحالة الخدمات ومساحة قرصMongo وحالة النسخ؛ احتفاظ7أيام محليًا.
   ذروة cgroup تخص generation الحالية؛ لا تجمع ذرى أجيال مختلفة كأنها متزامنة.
3. داخل Sync فقط، شغّل python - --ack-synthetic-only --source-sha <SHA> --seconds 180
   مع إدخال ovh_host/snap_runtime.py؛ احفظ stdout المنقح. يستخدم client/entities/facts
   وMongo وlease الحقيقيين لكن MockTransport دائمًا، ولا يستدعي OAuth أو حساب إعلانات.
4. من اتصال الرياض شغّل live_performance.py --config <nonsecret host.json>
   --seconds 120 --client-location Riyadh:<operator-declared ISP> --output <receipt.json>.
   الأداة تتحقق من هوية build قبل قراءة الجلسات، ثم تطلب Cookie لمالك وموظف
   التجربة من تسجيل دخول حقيقي؛ الجلسات في الذاكرة فقط ولا تُكتب في التقرير.
   أربع قراءات تحليلات متزامنة، ومسارات الموظفين الفعلية read-only؛ لا DB خارجي.
5. اربط نافذة القياس مع تقدم snap_runtime/CPU/RAM في UTC. التقرير الخارجي وحده
   لا يثبت تزامن Snap. قارن baseline بلا تقارير/سناب ثم معهما وبعد التعطل/التعافي.
   القبول:20عينة على الأقل لكل مسار، errors0، OOM0، تقدمسناب>=2 أثناء النافذة،
   وتحسن/عدم تدهور p95 بأكثر25%؛ هدف أولي p95<2s للقراءات الدافئة وليس SLA مثبتًا.
6. اختبارات الكتابة الـ80/إنشاء المورد/جاهز/الطباعة يعاد تشغيلها عبر CI المغلق
   والأدوات السابقة؛ القياس الخارجي الجديد لا يرسل فواتير أو ينشئ بوليصة مزوّد حقيقي.
   الطابعة المادية والبوليسة الخارجية الحقيقية خارج إثبات الاختبار الاصطناعي.
7. تعطل كل reports/sync/accounting على حدة؛ أثناءه GET الموظفين ينجح، ثم أعد
   الخدمة وانتظر TTL/claim الطبيعية وأثبت عاملًا واحدًا. لا تحذف الأقفال.
   اختبر web وMongo وreboot للخادم مع البيانات الاصطناعية؛ أعطال host/DNS/ISP
   لا يمكن إثباتها من LinuxCI. لا تستخدم مفاتيح أو Webhooks إنتاج.

النسخ الخارجي والاستعادة
الملفات مولّدة وغير مفعّلة. backup.py بلا --execute يعرض الخطة فقط.
بعد تفويض host/backup منفصل جهّز bucket/repository موجودًا ومراجَعًا ومفاتيح
محدودة لهذا المخزن فقط؛ لا يُنشئ البرنامج مخزنًا أو حسابًا أو restic init.
احفظ restic password وS3credentials بملفات0400/0600 root خارج checkout؛ النسخة
لا تتضمن مفاتيح التطبيق. احتفظ بكلمة restic في escrow مستقل واختبر فقد الخادم.
نسخة الموافقة example قيمتها approved=false ومنتهية ولا تفوّض التنفيذ.
الموافقة الخاصة تحدد synthetic-vps-backup وSHA/project ووقت انتهاء timezone-aware.

التنفيذ يثبت Docker المحلي/source manifest/حدود staging، ويتحقق من budget،
يقفل backup.lock، يوقف الكتّاب الأربعة ويشترط ExitCode0، يجمّد TTL للقاعدة
الاصطناعية، ينجز dump محدود الحجم بكود خروج ناجح، يعيد TTL والخدمات، ثم
يرفع ملفًا مكتملًا عبر restic المشفّر ويفحص البيانات ويستعيد archive ويقارنSHA.
لا تُكتب كلمة Mongo في argv أو السجلات، وملف أدواته يبقى في tmpfs الخاص.
الفشل يكتب تنبيهًا؛ الخروج غير النظيف يترك الكتّاب متوقفين للمراجعة ولا يمس claims.
لا تعِد worker ماليًا تلقائيًا إذا لم يثبت توقف الآخر. انقطاع التنفيذ بعنف
قبل finally يحتاج مراجعة حالة TTL والخدمات وbackup.lock قبل الاستئناف.

لا تفعّل backup.timer إلا بعد أول restore خارجي على قاعدة فارغة منفصلة؛
الموعد المقترح02:30الرياض وتوجد نافذة توقف للتطبيقات، ليس نسخًا online بلا أثر.
الاحتفاظ المقترح7يومية/4أسبوعية، forget --dry-run فقط حتى اعتماد السياسة.
لا prune تلقائيًا أو حذف لنسخ قبل إثبات الاستعادة. حد8GB soft-budget وليس
حصانة من تجاوز فاتورة الحساب أو نمو البيانات/الفهارس؛ alertعند70%قرص/80%RAM
وأيOOM/restart/backupعمره>26h. زمن RTO/RPO الحقيقيان ينتظران تجربة OVH/S3.
